# StepZero 소셜로그인 기반 관리자 진입 컨셉

## 1. 목적
- StepZero는 소셜로그인 전용 인증 모델을 사용한다.
- 일반 사용자 경험을 해치지 않으면서 운영자(관리자) 전용 콘솔(`/ops`) 진입을 안전하게 제공한다.

## 2. 기본 원칙
- 인증 방식: 이메일/비밀번호 로그인 제거, OAuth/OIDC 기반 소셜로그인만 허용
- 권한과 인증 분리: 로그인 성공 != 관리자 권한
- UI 숨김 + 서버 차단 동시 적용: 메뉴 숨김만으로 보안을 대체하지 않음
- 최소 권한 원칙: 관리자 권한은 필요한 사용자에게만 부여

## 3. 사용자 타입
- `user`: 일반 사용자
- `ops_admin`: 운영 관리자
- `super_admin`: 시스템 관리자(권한/정책 관리 가능)

권한 판단 기준:
- 백엔드 토큰 클레임 또는 서버 조회 결과(`role`)를 기준으로 판단
- 프론트는 서버에서 전달된 권한값으로 UI를 분기

## 4. 관리자 진입 경로
- 관리자 진입 기본 URL: `/ops`
- 하위 경로:
1. `/ops` (운영 대시보드)
2. `/ops/reports` (신고 관리)
3. `/ops/users` (사용자 상태 관리)
4. `/ops/settings` (운영 설정)

노출 정책:
- 일반 사이드바 기본 메뉴에는 노출하지 않음
- 로그인 사용자 중 `ops_admin` 이상에게만 “운영콘솔” 메뉴 노출
- 상단 프로필 드롭다운에도 동일 권한 기준으로 노출

## 5. 인증/인가 플로우
1. 사용자가 소셜로그인(OAuth) 완료
2. 백엔드가 사용자 식별자(provider + subject)로 계정 조회/생성
3. 계정의 `role` 확인
4. `role`이 `ops_admin` 이상이면 `/ops` 접근 허용
5. 그 외 권한이면 `/ops` 접근 시 403 반환 또는 `/dashboard` 리다이렉트

권장 동작:
- API: 403(JSON 문제응답)
- 웹 페이지: 사용자 친화적으로 `/dashboard` 리다이렉트 + 토스트 메시지

## 6. 프론트엔드 적용 규칙
- 라우트 가드:
1. 클라이언트 가드: 메뉴/버튼/링크 숨김
2. 서버 가드: `/ops` 페이지 로드 시 세션/권한 검사
- 표시 규칙:
1. `role < ops_admin`: 운영콘솔 메뉴 비노출
2. `role >= ops_admin`: 운영콘솔 메뉴 노출

UX 권장:
- `/ops` 첫 화면은 운영 KPI 카드 + 대기 신고 수 + 최근 처리 로그
- 미권한 접근 시 “권한 없음” 문구보다 대시보드 복귀 흐름 우선

## 7. 백엔드 적용 규칙
- API Prefix: `/api/v2/ops/*`
- 보호 방식: `Depends(get_current_user)` + `require_role("ops_admin")`
- 감사 로그:
1. 신고 상태 변경
2. 사용자 상태 변경(정지/해제)
3. 운영 설정 변경

로그 필드 최소 기준:
- `actor_user_id`, `actor_role`, `action`, `target_type`, `target_id`, `timestamp`, `ip`

## 8. 데이터 모델 권장
- `users.role` 컬럼(예: `user|ops_admin|super_admin`)
- 필요 시 `team_members.role`과 병행하여 팀 단위 관리자 운영
- 소셜 계정 매핑 테이블 유지:
1. `provider` (google, kakao, naver ...)
2. `provider_user_id`
3. `user_id`

## 9. 보안/운영 체크리스트
- 소셜로그인 토큰 서명/만료 검증
- 관리자 권한 API 전부 role guard 적용
- 관리자 액션 감사 로그 저장
- 운영자 권한 부여/회수 절차 문서화
- 비상 시 `ops_admin` 일괄 회수 절차 준비

## 10. 구현 우선순위(MVP)
1. `/ops` 진입 라우트 + 서버 권한 검사
2. 사이드바/드롭다운 관리자 메뉴 조건부 노출
3. `/api/v2/ops/reports`, `/api/v2/ops/users` role guard 적용
4. 주요 운영 액션 감사 로그 기록
5. 운영 대시보드 기본 KPI 카드 배치

## 11. 비고
- 현재 프로젝트 네이밍 규칙에 맞춰 운영콘솔 피처명은 `ops`로 통일한다.
- 엔드포인트/폴더/문서 모두 `ops` 기준으로 유지한다.
