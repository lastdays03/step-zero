사장님, 아주 좋은 접근입니다. 창업/비즈니스 분야에서 **"지역(Region)"**과 **"업종(Industry)"**은 사용자를 묶어주는 가장 강력한 접착제입니다.

일반적인 커뮤니티가 아니라, **당근마켓(지역 인증)**과 **블라인드/링크드인(업종 인증)**을 합친 **"하이퍼 로컬 & 버티컬(Hyper-Local & Vertical)"** 컨셉으로 설계해 보겠습니다.

사용자가 들어오자마자 **"와, 여기는 나랑 똑같은 고민을 하는 사람들만 있네?"**라고 느끼게 만드는 구조입니다.

---

### 1. 핵심 컨셉: "Dual-Group System (이원화 그룹)"

사용자는 가입 시 딱 두 가지 정보를 입력합니다.

1. **지역:** (예: 서울 마포구)
2. **업종:** (예: 요식업/카페)

이 정보를 바탕으로 시스템이 자동으로 **두 개의 '라운지(Lounge)'**에 사용자를 배정합니다. 별도로 가입 신청을 할 필요가 없습니다.

---

### 2. 화면 구성 (Layout Strategy)

#### **① 왼쪽: 스마트 네비게이션 (Smart Sidebar)**

고정된 메뉴가 아니라, 사용자 프로필에 따라 메뉴명이 바뀝니다.

* **내 명찰 (Profile Card):**
* 닉네임 + **[서울 마포구]** 뱃지 + **[☕ 카페사장]** 뱃지


* **📍 우리 동네 (Region Group):**
* `# 마포구 창업 모임` (자동 배정)
* `# 서울 지원사업 정보`
* `# 가게 양도/양수`


* **🛠️ 내 업종 (Industry Group):**
* `# 카페/베이커리 포럼` (자동 배정)
* `# 식자재 공구`
* `# 레시피/메뉴 공유`


* **📢 전체 광장 (General):**
* `# 세무/노무 (공통)`
* `# 자유게시판`



#### **② 가운데: 맞춤형 피드 (Contextual Feed)**

사용자가 현재 가장 관심 있는 맥락을 선택해서 봅니다.

* **탭(Tab) 구조:** 상단에 `[전체]` / `[📍 동네 소식]` / `[🛠️ 업종 이야기]` 탭을 배치하여 필터링.
* **게시글 카드 (Post Card UI):**
* 작성자의 **소속(지역/업종)**이 닉네임보다 더 눈에 띄게 강조됩니다.
* *예시:* **[성동구 | 카페]** 김사장님: "혹시 이번 위생교육 받으신 분 계신가요?"


* **자동 태깅:**
* 사용자가 글을 쓰면, 본인의 지역과 업종 태그가 글에 자동으로 붙습니다. (귀찮은 설정 제거)



#### **③ 오른쪽: 매칭 위젯 (Connect Widget)**

커뮤니티의 연결성을 강화하는 장치입니다.

* **"내 주변 동료":** 같은 지역(마포구)에 있는 다른 사장님들 프로필 노출.
* **"업종 멘토":** 같은 업종(카페)인데 경험치(레벨)가 높은 선배 사장님 추천.
* **"맞춤 지원사업":** [서울] + [요식업] 조건에 딱 맞는 정부 지원금 공고 배너 자동 노출.

### 3. 기능 설계 (Feature Specs)

#### **A. 자동 온보딩 (Auto-Onboarding)**

* 가입 프로세스에서 `지역`과 `업종`을 선택하지 않으면 커뮤니티 진입 불가.
* 선택 즉시 해당 그룹의 **'읽기/쓰기 권한'** 자동 부여.
* *장점:* "어떤 게시판에 가야 하지?"라는 고민을 없애줌.

#### **B. 동네 인증 & 사업자 인증 (Trust System)**

* 초기에는 자율 선택이지만, 추후 **사업자등록증 인증**이나 **위치 인증**을 통해 뱃지에 **[✅ 인증됨]** 마크를 달아주면 신뢰도가 급상승합니다.
* 인증된 사용자만 쓸 수 있는 `비밀 게시판` 운영 가능.

#### **C. 필터링된 알림 (Smart Notification)**

* "서울시" 관련 정책 글이 올라오면 서울 사용자에게만 푸시 알림.
* "카페 원두 가격 인상" 글이 인기글이 되면 카페 업종 사용자에게만 알림.

### 4. DB 설계 핵심 (Supabase)

이 컨셉을 구현하기 위해 `profiles` 테이블과 `posts` 테이블의 관계가 핵심입니다.

```sql
-- 1. 사용자 프로필 (지역/업종 FK 필수)
CREATE TABLE profiles (
  id UUID PRIMARY KEY,
  nickname TEXT,
  region_id INT REFERENCES regions(id),   -- 예: 1(서울), 2(경기)...
  industry_id INT REFERENCES industries(id), -- 예: 10(카페), 11(IT)...
  is_verified BOOLEAN DEFAULT false
);

-- 2. 게시글 (어떤 맥락의 글인지 저장)
CREATE TABLE posts (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES profiles(id),
  content TEXT,
  target_region_id INT,   -- 이 글이 특정 지역용인지 (NULL이면 전체)
  target_industry_id INT, -- 이 글이 특정 업종용인지 (NULL이면 전체)
  created_at TIMESTAMPTZ
);

```
