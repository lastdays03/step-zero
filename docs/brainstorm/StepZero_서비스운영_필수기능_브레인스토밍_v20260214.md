# StepZero 서비스 운영 필수기능 브레인스토밍 (v2026-02-14)

## 1) 목적
- 기준 문서: `docs/planning/StepZero_Service_Plan_v20260213.md`
- 목표: 사용자 기능(로드맵/챗봇/커뮤니티) 외에, 실제 서비스 운영에 필요한 기능을 아이디어 수준으로 정의
- 현재 전제:
- 대시보드까지 UI/흐름은 구현되었으나 실제 운영 데이터 연결은 제한적
- 즉시 개발 착수보다 운영 요구사항 구조화가 우선

## 2) 운영 관점 핵심 질문
- 서비스가 장애 없이 계속 동작하려면 무엇이 필요한가?
- 잘못된 데이터/응답을 빠르게 탐지하고 복구하려면 무엇이 필요한가?
- 운영자가 "무슨 일이 일어났는지" 빠르게 파악하려면 무엇이 필요한가?
- 비용/보안/컴플라이언스를 통제하려면 무엇이 필요한가?

## 3) 운영 필수 기능 아이디어 맵

### A. 계정/권한/운영자 콘솔
- 운영자 관리자(Admin Console)
- 사용자 조회, 계정 상태 변경(활성/정지), 신고 처리, 공지 노출 제어
- 역할 기반 권한(RBAC)
- 운영자, 콘텐츠 매니저, CS 담당, 데이터 관리자 권한 분리
- 운영 감사 로그(Audit Log)
- 누가 언제 어떤 운영 액션을 했는지 추적
- 내부 임퍼스네이션(제한적)
- CS 대응을 위한 read-only 사용자 세션 확인 기능

### B. 데이터 품질/정합성 관리
- 데이터 품질 대시보드
- 로드맵 생성 성공률, 문서 매핑 누락률, 추천 공고 유효성 비율
- 참조 데이터 버전 관리
- 법령/공고/서식 데이터셋 버전, 배포 이력, 롤백 포인트
- 데이터 검증 파이프라인
- 수집 후 검증(필수 필드, 날짜 유효성, 지역/업종 매핑 정합성)
- 수동 승인 큐(휴먼 인 더 루프)
- 고위험 변경(규정 변경, 폐지 공고) 반영 전 승인 단계

### C. AI 운영(AIOps/LLMOps)
- 프롬프트/응답 품질 모니터링
- 응답 실패율, 환각 의심 패턴, 근거 링크 누락 비율
- 모델/프롬프트 버전 실험 관리
- A/B 테스트, 버전별 성능 비교, 즉시 롤백
- 안전 가드레일 관리
- 금칙어, 법적 리스크 문구 탐지, 민감정보 출력 차단 룰
- 토큰/비용 대시보드
- 기능별 모델 호출량, 사용자별/기능별 비용 상한

### D. 서비스 신뢰성/장애 대응
- 헬스체크 및 SLO 대시보드
- API p95, 오류율, RAG 응답시간, 배치 성공률
- 장애 알림 체계
- Slack/이메일 알림, 심각도 분류, 온콜 라우팅
- 장애 런북(Runbook)
- DB 접속 오류, 벡터 인덱스 실패, 외부 API 장애 대응 절차
- 기능 플래그(Feature Flag)
- 문제 기능만 신속히 비활성화하는 운영 스위치

### E. 커뮤니티 운영/모더레이션
- 신고/제재 워크플로우
- 신고 접수, 자동 분류, 제재 이력 관리
- 콘텐츠 정책 엔진
- 금지행위 자동 탐지(광고 스팸, 개인정보 노출, 허위정보)
- 신뢰 배지 운영 도구
- 인증 문서 검토 상태, 만료 관리, 재인증 알림
- 커뮤니티 지표 대시보드
- 게시글/댓글 비율, 신고율, 재방문율, 악성 사용자 비율

### F. 정책/컴플라이언스/법무
- 개인정보 처리 lifecycle 관리
- 보관기간, 파기 스케줄, 다운로드/삭제 요청 처리
- 약관/정책 버전 동의 이력
- 언제 어떤 버전에 동의했는지 증적 저장
- 법적 고지/면책 문구 정책화
- 기능별 고지문 노출 규칙 중앙 관리
- 데이터 접근 통제와 마스킹
- 운영 화면에서 PII 최소 노출 기본값

### G. 재무/과금/비즈니스 운영
- 플랜/구독 운영 기능
- 무료/유료 플랜 정책, 한도, 업그레이드 경로
- 사용량 기반 과금 지표
- AI 호출량, 문서 생성량, 저장용량 기준 과금 가능성 검토
- 결제/환불 운영 도구
- 실패 결제 재시도, 영수증, 환불 상태 추적

### H. 성장/실험/CRM 운영
- 퍼널 분석 대시보드
- 가입 → 로드맵 생성 → 첫 액션 수행 → 서류 제출 완료
- 리텐션 운영 도구
- 세그먼트별 리마인드(미완료 단계 재방문 유도)
- 운영 캠페인 관리
- 공지/배너/메시지 타겟팅 및 성과 측정

### I. 개발/배포 운영
- 환경 분리와 배포 파이프라인
- dev/staging/prod 명확 분리, 승인 배포
- 마이그레이션 안전장치
- 배포 전 스키마 검증, 롤백 절차 자동화
- 운영 설정 관리
- 시크릿/환경변수 중앙 관리, 변경 감사 이력

## 4) 우선순위 제안 (현재 상태 기준)

### P0 (바로 필요: 운영 최소선)
- 운영자 콘솔 최소 기능(사용자 조회/정지, 공지 제어)
- 데이터 품질 모니터링(매핑 누락/배치 실패 알림)
- 장애 알림 + 런북(핵심 API/DB/외부 의존성)
- 감사 로그/권한 분리(RBAC 최소)
- 시크릿/설정 관리 표준화(.env.local 정책 + 운영 비밀 저장소)

### P1 (실서비스 초기 안정화)
- AI 품질/비용 대시보드 + 프롬프트 버전 관리
- 커뮤니티 신고/제재 워크플로우
- 퍼널/리텐션 분석 대시보드
- 정책 버전 동의 이력 및 개인정보 요청 처리 플로우

### P2 (스케일 대비)
- 고급 실험 플랫폼(A/B 자동화)
- 구독/과금 운영 도구
- 다중 에이전트 품질 관리 및 고도화 가드레일

## 5) 논의 필요 항목 (다음 브레인스토밍 질문)
- 운영자 콘솔 범위를 어디까지 MVP로 자를 것인가?
- 데이터 검증에서 자동화 vs 수동승인 비율을 어떻게 설계할 것인가?
- AI 비용 상한 정책을 사용자 단위로 둘지, 기능 단위로 둘지?
- 커뮤니티 제재 기준(경고/정지/영구제재)과 이의신청 플로우 필요 여부?
- 법적 고지(면책/근거 표시) 표준 문구를 기능별로 어떻게 강제할 것인가?

## 6) 정리
- StepZero가 "기능 데모"를 넘어 실제 서비스가 되려면, 사용자 기능과 동등한 수준의 운영 기능이 필요함
- 특히 P0 항목은 제품 기능 추가보다 먼저 안정성/신뢰성을 확보하는 기반 작업으로 보는 것이 타당함
- 다음 단계는 P0 항목을 운영 시나리오 기준으로 쪼개서 "운영 스펙 문서"로 전환하는 것
