# StepZero 대시보드 개선 보고서 — 3안: 시뮬레이션 + 가이드 대시보드

> 작성일: 2026-03-04
> 분석 대상: `/dashboard` 메인 대시보드 (사용자 홈 화면)

---

## 1. 세 가지 안의 포지셔닝

| | 1안: 정보 밀도 강화 | 2안: AI 코치 중심 | 3안: 시뮬레이션 + 가이드 |
|---|---|---|---|
| **한 줄 요약** | 카드 늘리고 지표 추가 | AI가 말 걸어주는 코치 | 미래를 보여주고 방법을 알려줌 |
| **핵심 질문** | "내 현황이 어때?" | "지금 뭘 해야 해?" | "이대로 가면 어떻게 돼?" |
| **시간 축** | 과거/현재 (지표 리뷰) | 현재/즉시 (행동 유도) | **현재→미래 (시뮬레이션)** |
| **UX 모델** | Notion, Linear | Duolingo, Copilot | **Stripe Atlas, 부동산 계산기** |
| **감정 설계** | "파악했다" (안도) | "할 수 있다" (동기) | **"보인다" (확신)** |
| **차별화 축** | 데이터 밀도 | AI 개인화 | **예측 + 교육** |

### 3안의 핵심 인사이트

> "처음 창업하는 사람이 가장 두려워하는 것은 '실패'가 아니라 '모르는 것'이다."

- 1안은 "현재 상태"를 보여주지만 → 다음에 뭘 해야 하는지 모름
- 2안은 "다음 행동"을 알려주지만 → 왜 그래야 하는지, 어떻게 하는지 모름
- 3안은 **"이대로 가면 이렇게 되고, 이렇게 하면 된다"**를 보여줌

---

## 2. 설계 철학

### "대시보드가 아닌 시뮬레이터 + 가이드북"

창업자에게 필요한 것은:
1. **예측 가능성** — "이 속도면 언제 오픈할 수 있는가"
2. **비용 가시성** — "지금까지 얼마가 들었고, 앞으로 얼마가 더 필요한가"
3. **방법론** — "이 단계에서 구체적으로 어떻게 해야 하는가"
4. **선배 경험** — "나와 비슷한 사람은 어떻게 했는가"

이 네 가지를 대시보드 하나에 담는 것이 3안의 목표다.

## 4. 영역별 상세 설계

### A. 오픈 시뮬레이터 (Launch Simulator)

**1안/2안에 없는 완전 신규 개념** — 대시보드의 히어로 영역

#### 핵심 아이디어

기존: "D-28" (로드맵 생성 후 30일 카운트다운 — 의미 불명확)
3안: **"예상 오픈일: 4월 15일"** (실제 완료 속도 기반 예측)

```
🚀 오픈 시뮬레이터

 ┌──────────────────────────────────────────────────────┐
 │  시작     임대차    사업자등록   ● 영업 인허가    오픈 │
 │  ████████████████████████████████░░░░░░░░░░░░░░░░░░░ │
 │  2/25                            3/4              4/15│
 └──────────────────────────────────────────────────────┘

 예상 오픈일: 4월 15일 (42일 후)
 현재 속도: 주당 1.2단계 · 비슷한 업종 평균(55일)보다 빠름
```

#### 예측 계산 로직

```
남은 단계 수 = total_steps - completed_steps
평균 완료 속도 = completed_steps / (now - roadmap.created_at).days  [단계/일]
예상 남은 일수 = 남은 단계 수 / 평균 완료 속도
예상 오픈일 = now + 예상 남은 일수

# 대안: 단계별 estimated_days 합산
남은 예상일 = SUM(미완료 단계.estimated_days)
예상 오픈일 = now + 남은 예상일
```

두 가지 계산 방식을 비교 표시할 수도 있다:
- **속도 기반**: "현재 속도로 진행하면 4월 15일"
- **계획 기반**: "일정대로 진행하면 4월 8일" (estimated_days 합산)

#### 활용 데이터 (기존 모델에 이미 존재)

| 데이터 | 소스 | 필드 |
|--------|------|------|
| 전체 단계 수 | `RoadmapStep` COUNT | `steps.length` |
| 완료 단계 수 | `RoadmapStep.status == 'COMPLETED'` | `tasks_completed` |
| 로드맵 생성일 | `Roadmap.created_at` | 이미 사용 중 |
| 단계별 예상 소요일 | `RoadmapStepDetail.estimated_days` | 이미 존재, 대시보드 미노출 |
| 업종 | `Roadmap.business_type` | 이미 존재, 대시보드 미노출 |
| 예산 범위 | `Roadmap.budget_range` | 이미 존재, 대시보드 미노출 |

**구현 복잡도**: 중간 — 백엔드에서 `estimated_days` 합산 + 속도 계산하여 응답에 추가

### B. 비용 트래커 (Cost Tracker)

**기존에 완전히 없는 기능** — 창업자의 가장 현실적인 관심사

#### 왜 비용 트래커인가

StepZero는 이미 `Roadmap.budget_range` 필드와 `ActionKit`에 비용 관련 데이터를 보유하고 있지만, **어디에도 비용을 시각화하지 않는다.** 창업자가 가장 자주 하는 질문은 "얼마나 들어?"이다.

#### 데이터 구성

```
💰 비용 트래커

 예상 총 비용                    예산 대비
 ┌─────────────┐               ┌──────────┐
 │ ₩2,850,000  │               │ ████░░ 57%│
 └─────────────┘               └──────────┘
 예산 ₩5,000,000                여유 ₩2,150,000

 단계별 내역:
 ✅ 임대차 계약     ₩500,000    실제
 ✅ 사업자등록      ₩0          실제
 🔵 인허가 수수료   ~₩50,000    예상
 🔒 세무사 비용     ~₩300,000   예상
 🔒 인테리어       ~₩2,000,000  예상
```

#### 구현 전략 (3단계)

**Phase 1 — 예상 비용 표시 (백엔드 소규모 변경)**

단계별 `estimated_days`처럼, 비용도 로드맵 생성 시 AI가 산출하여 `metadata_json`에 저장하는 방식:

```python
# RoadmapStepAction.metadata_json에 이미 extensible
{
  "estimated_cost": 50000,
  "cost_label": "인허가 수수료",
  "cost_type": "fixed"  # fixed | variable | optional
}
```

현재 `metadata_json`은 `{}` (빈 dict)인 액션이 대부분이므로, 새 로드맵 생성 시 AI 파이프라인에서 비용 데이터를 함께 생성하도록 확장.

기존 로드맵은 `budget_range` 기반으로 업종별 평균 비용 템플릿을 적용.

**Phase 2 — 실제 비용 입력 (프론트엔드 + API)**

사용자가 직접 실제 지출액을 입력:
```
✅ 임대차 계약    예상 ₩500,000 → 실제 ₩480,000  [수정]
```

**Phase 3 — 비용 인사이트 (AI)**

"비슷한 업종 평균 대비 인테리어 비용이 20% 높습니다. 절감 방법을 확인해 보세요."

### C. 단계별 가이드 (Step Guide Panel)

**1안은 서류 목록만, 2안은 미션 체크만** — 3안은 **종합 가이드북**

#### 현재 단계의 모든 정보를 한 패널에

```

 ✅ 임대차 계약 체결
 ✅ 전자상거래법 확인

 ── 예상 소요 ────────────────────────────────────
 ⏰ 이 단계 예상: 14일 (현재 8일차)
```

#### 데이터 매핑 (모두 기존 모델에 존재)

| UI 영역 | 데이터 소스 | 모델 필드 |
|---------|-----------|----------|
| 핵심 체크리스트 | `RoadmapStepAction` (type=CHECKLIST) | `title`, `description` |
| 필요 서류 | `RoadmapStepAction` (type=DOCUMENT) | `title`, `metadata_json` |
| 관련 법령 | `RoadmapStepAction` (type=LEGAL_BASIS) | `title`, `description` |
| 주의사항 | `RoadmapStepDetail` | `risk_notes: list[str]` |
| 예상 소요 | `RoadmapStepDetail` | `estimated_days: int` |

**현재 대시보드는 DOCUMENT 타입만 보여주고 있다.** 3안은 CHECKLIST, LEGAL_BASIS, risk_notes까지 모두 노출하여 "이 단계의 모든 것"을 한 곳에서 볼 수 있게 한다.

**구현 복잡도**: 낮음 — 이미 `roadmapDetail` API에서 전부 내려옴. 프론트엔드에서 액션 타입별 분류 렌더링만 추가.

### D. 성공 사례 카드 (Success Stories)

**1안/2안 모두에 없는 고유 섹션**

#### 왜 성공 사례인가

창업자는 "나와 비슷한 사람이 성공했다"는 증거를 보면 확신이 생긴다. 이것은 데이터(1안)나 AI 지시(2안)가 줄 수 없는 **감정적 확신**이다.

```
🏆 비슷한 창업 성공 사례

 ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
 │ 🍰 디저트카페      │  │ 🛒 온라인 쇼핑몰   │  │ 🍕 프랜차이즈      │
 │ 서울 마포구        │  │ 서울 강남구        │  │ 경기 수원시        │
 │                   │  │                   │  │                   │
 │ 완료까지 38일      │  │ 완료까지 45일      │  │ 완료까지 52일      │
 │ 총 비용 ₩3.2M     │  │ 총 비용 ₩1.8M     │  │ 총 비용 ₩5.1M     │
 │                   │  │                   │  │                   │
 │ "구청 사전상담이   │  │ "통신판매업은      │  │ "본사 지원이       │
 │  핵심이었어요"     │  │  온라인이 빠르다"   │  │  큰 도움이 됐다"   │
 │                   │  │                   │  │                   │
 │      [스토리 보기] │  │      [스토리 보기] │  │      [스토리 보기] │
 └──────────────────┘  └──────────────────┘  └──────────────────┘
```

#### 구현 전략

| Phase | 방식 | 장점 | 단점 |
|-------|------|------|------|
| **1 (MVP)** | 업종별 정적 JSON 데이터 (5~10개 사례) | 즉시 구현, 백엔드 불필요 | 개수 한정, 업데이트 수동 |
| **2** | DB 테이블 + 관리자 콘솔에서 CRUD | 동적 관리, 필터링 가능 | 모델 + UI 추가 필요 |
| **3** | 실제 완료 로드맵에서 자동 익명 생성 | 진짜 데이터, 자동 확장 | 완료 사용자 수 충분해야 의미 |

**Phase 1 데이터 구조**:
```typescript
type SuccessStory = {
  emoji: string;
  businessType: string;
  location: string;
  completionDays: number;
  totalCost: string;
  quote: string;
  tip: string;
};
```

업종(`Roadmap.business_type`) 기반으로 가장 유사한 3건을 선별하여 표시.

### E. 오픈 시뮬레이터 — 진행 바 상세 설계

기존 원형 차트(75%)를 **수평 타임라인 시뮬레이터**로 교체:

```
┌──────────────────────────────────────────────────────────┐
```

## 9. 리스크 평가

| 리스크 | 영향 | 대응 |
|--------|------|------|
| `estimated_days`가 0인 단계 다수 | 시뮬레이터 예측 부정확 | 0인 경우 업종 평균값 대체, 폴백 메시지 표시 |
| `budget_range`가 null인 로드맵 | 비용 트래커 표시 불가 | 비용 섹션 숨김 + "예산 설정하기" CTA 표시 |
| 성공 사례 정적 데이터 신뢰도 | 사용자가 "진짜야?" 의심 | "StepZero 사용자 사례 기반" 명시 + Phase 3에서 실제 데이터 전환 |
| 비용 데이터 정확도 | 실제 비용과 예상 괴리 | "예상 비용이며 지역/시기에 따라 달라질 수 있습니다" 면책 문구 |
| 속도 예측 초기 데이터 부족 | 로드맵 생성 직후 1~2일은 속도 계산 불가 | 최소 3일차부터 속도 표시, 이전에는 estimated_days 기반만 |

## 11. 결론

3안은 **"이미 수집해놓고 사용하지 않는 데이터"를 전면 활용**하여 창업자에게 가장 실질적인 가치(언제/얼마/어떻게)를 제공한다.

1안이 "더 많은 숫자", 2안이 "더 똑똑한 안내"라면, 3안은 **"더 깊은 이해"**를 목표로 한다. 대시보드를 열었을 때 "내 창업의 전체 그림"이 보이는 경험이다.

특히 `estimated_days`, `budget_range`, `risk_notes`, `CHECKLIST`, `LEGAL_BASIS` 등 이미 DB에 존재하지만 대시보드에 전혀 노출되지 않는 데이터가 핵심 자원이며, 이를 활용하는 것만으로도 상당한 UX 개선이 가능하다.
