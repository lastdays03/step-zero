# StepZero 대시보드 개선 보고서 — 2안: AI 코치 중심 대시보드

> 작성일: 2026-03-04
> 분석 대상: `/dashboard` 메인 대시보드 (사용자 홈 화면)

---

## 1안 vs 2안 핵심 차이

| 구분 | 1안: 정보 밀도 강화 | 2안: AI 코치 중심 |
|------|-------------------|------------------|
| **패러다임** | Dashboard as **Information Hub** | Dashboard as **AI Coach** |
| **핵심 질문** | "내 현황이 어때?" | "지금 뭘 해야 해?" |
| **정보 구조** | 카드 8개, 지표 다수 → 사용자가 해석 | AI가 해석 → 한 문장으로 전달 |
| **UX 모델** | 분석 도구 (Notion, Linear) | 개인 비서 (Copilot, Duolingo) |
| **강점** | 데이터 한눈에 파악 | 행동 전환율 극대화 |
| **약점** | 정보 과부하 가능성 | 데이터 직접 탐색 어려움 |
| **타겟 사용자** | 데이터 리터러시 높은 창업자 | 처음 창업하는 비전문가 |

## 2. 설계 철학

### "창업자는 대시보드가 아니라 코치가 필요하다"

StepZero의 핵심 가치는 **AI 기반 액셀러레이팅**이다. 그런데 현재 대시보드는 단순 지표 나열로, AI의 가치가 챗봇 FAB 버튼 뒤에 숨어있다. 2안은 AI를 대시보드의 **주인공**으로 올려, 화면을 열자마자 "코치가 말 걸어주는" 경험을 제공한다.

**핵심 원칙**:
1. **One Thing First** — 화면 최상단에 "지금 가장 중요한 한 가지"만 보여준다
2. **AI가 해석한다** — 숫자를 나열하지 않고, AI가 맥락을 붙여 말해준다
3. **스토리로 보여준다** — 지표 그리드 대신 타임라인으로 여정을 서술한다
4. **행동을 유도한다** — 모든 섹션에 즉시 실행 가능한 CTA가 있다

## 4. 영역별 상세 설계

### A. AI 코치 히어로 카드 (핵심 차별점)

**현재**: 정적 진행 카드 (75%, D-28, "신청 계속하기")
**2안**: AI가 현재 상황을 분석하여 **자연어 메시지 + 구체적 행동 CTA**를 제공

#### 메시지 생성 로직

상태 기반 조건 분기로 메시지를 생성한다 (LLM 호출 불필요, 프론트엔드 로직만).

| 조건 | AI 코치 메시지 | CTA |
|------|--------------|-----|
| 진행률 0%, 로드맵 막 생성 | "로드맵이 준비됐어요! 첫 단계 '{step}'부터 시작해 볼까요?" | [첫 단계 시작하기] |
| 진행률 1~30% | "좋은 출발이에요! '{step}' 단계의 서류 {n}건을 준비해 주세요." | [서류 확인하기] |
| 진행률 31~70% | "절반을 넘었어요! '{step}' 완료까지 약 {n}일 남았어요." | [이어서 진행하기] |
| 진행률 71~99% | "거의 다 왔어요! '{action}'만 완료하면 다음 단계로 넘어가요." | [마무리하기] |
| 진행률 100% | "🎉 모든 준비가 끝났어요! 사업을 시작할 시간이에요." | [최종 체크리스트] |
| D-day ≤ 7 | "⚠️ 마감까지 {n}일! '{action}'을 먼저 처리하는 걸 추천해요." | [긴급 처리하기] |
| 단계 막 완료 | "🎉 '{phase}' 단계를 완료했어요! 다음은 '{next}'예요." | [다음 단계 보기] |
| 3일 이상 미접속 후 복귀 | "다시 오셨네요! 마지막으로 '{step}'을 진행 중이었어요." | [이어서 하기] |

### B. 나의 여정 (Vertical Journey Map)

**1안과의 차이**: 1안은 수평 타임라인에 숫자 추가, 2안은 **세로 여정 지도**로 전환

```
🗺️ 나의 여정

  ✅ 1. 아이디어 검증 ─────── 2/15 완료
  │
  ✅ 2. 임대차 계약 ────────── 2/20 완료
  │
  🔵 3. 영업 인허가 ← 지금 여기
  │   ████████░░ 75%
  │   남은 작업: 통신판매업 신고서, 영업신고증
  │
  🔒 4. 세무/회계
  │
  🔒 5. 팀 구성

  준비도: ✅ 인허가 완료  ·  D-28 여유
```

**왜 세로인가**:
- 모바일에서 스크롤이 자연스러움 (수평 스크롤은 터치 조작 불편)
- 현재 단계를 펼쳐서 상세 정보 표시 가능 (아코디언 패턴)
- 완료 단계에 날짜를 자연스럽게 표시 가능
- 전체 여정의 "길이"가 직관적으로 보임

**현재 단계 확장 표시**:
- 미니 진행 바
- 남은 작업 목록 (최대 3건)
- 클릭 시 로드맵 상세 페이지로 이동

**구현 복잡도**: 중간 — `RoadmapStepper` 재작성 (레이아웃만 변경, 데이터는 동일)

### C. 이번 주 미션 (Weekly Mission Board)

**1안과의 차이**: 1안은 "오늘의 할 일" (전체 미완료 목록), 2안은 **주 단위 미션** (게이미피케이션)

```
🎯 이번 주 미션                              1/3 완료

  ✅ 전자상거래법 양식 다운로드
     완료! +10 XP

  ☐ 통신판매업 신고서 제출
    📎 전자상거래법 양식 필요  ·  ⏰ 예상 3일
    [서류 다운로드]  [완료 표시]

  ☐ 영업신고증 발급 신청
    📎 영업인허가 양식 필요  ·  ⏰ 예상 5일
    [가이드 보기]  [완료 표시]

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  이번 주 미션을 모두 완료하면
  '세무/회계' 단계로 넘어가요! 🚀
```

**게이미피케이션 요소**:

| 요소 | 설명 | 동기부여 효과 |
|------|------|-------------|
| **주간 미션** | 현재 단계 작업을 주 단위로 분배 | 작은 목표로 쪼개서 부담 감소 |
| **완료 표시 버튼** | 사용자가 직접 체크 (localStorage) | 성취감 + 진행률 실시간 반영 |
| **미션 완료 시 메시지** | "다음 단계로 넘어가요!" | 다음 행동 자연스럽게 유도 |
| **연속 완료 스트릭** | "3일 연속 미션 수행 중!" (Phase 3) | 습관 형성 |

**"완료 표시" 동작**:
1. 사용자가 [완료 표시] 클릭
2. localStorage에 `{ missionId: completedAt }` 저장
3. 진행 바 즉시 업데이트
4. 모든 미션 완료 시 축하 애니메이션 + AI 코치 메시지 갱신

**구현 복잡도**: 중간 — 프론트엔드 컴포넌트 신규, 데이터는 기존 `RoadmapStepDetail.actions`에서 추출

### D. 나의 창업 타임라인 (Activity Feed)

**1안에 없는 완전 신규 섹션** — 대시보드의 핵심 차별점

```
    📄 전자상거래법 양식 다운로드

    ✅ 임대차 계약 단계 완료! (소요 기간: 8일)

  2/25 ────────────────────────────────────────
    🚀 로드맵 생성 완료 — '온라인 쇼핑몰 창업'

  │ 🟢 12명 온라인                           │

  │                    [동료 창업자 만나기 →] │
  └─────────────────────────────────────────┘
```

**타임라인 이벤트 유형**:

| 이벤트 | 아이콘 | 데이터 소스 | 자동 생성 |
|--------|-------|-----------|----------|
| 로드맵 생성 | 🚀 | `Roadmap.created_at` | O |
| 단계 완료 | ✅ | `RoadmapStep.status` 변경 | O |
| 서류 다운로드 | 📄 | 클릭 이벤트 (localStorage) | O |
| 준비도 업그레이드 | 🎉 | readiness level 변경 | O |
| AI 팁 | 💡 | Phase별 정적 팁 풀 | O |
| 미션 완료 | 🏅 | 주간 미션 체크 | O |
| Growth Club 요약 | 💬 | 타임라인 최하단 고정 | O |

**Phase 1 구현 (프론트엔드 only)**:
- localStorage에 이벤트 배열 저장: `stepzero_timeline_{roadmapId}`
- 서류 다운로드, 미션 완료 시 이벤트 push
- 로드맵 생성일/단계 완료는 기존 데이터에서 역산

**Phase 2 구현 (백엔드)**:
- `ActivityEvent` 테이블 생성
- 서버 사이드 이벤트 기록
- 기기 간 동기화

**구현 복잡도**: Phase 1 중간, Phase 2 높음

### E. Growth Club 통합 (타임라인 인라인)

**1안과의 차이**: 1안은 별도 카드로 강화, 2안은 **타임라인에 통합**

1안에서는 Growth Club이 독립 카드로 존재하지만, 2안에서는 타임라인 최하단에 자연스럽게 배치한다. 이유:

1. 별도 카드는 "다른 영역"처럼 느껴져 클릭률이 낮음
2. 타임라인 안에 있으면 스크롤하다 자연스럽게 발견
3. "나의 활동"과 "동료 활동"이 하나의 흐름으로 연결

## 5. 1안 대비 삭제/축소 항목

2안에서는 의도적으로 **정보량을 줄이고 행동 유도에 집중**한다:

| 1안 항목 | 2안에서의 처리 | 이유 |
|---------|--------------|------|
| DAU/MAU 비율 | 삭제 | 운영자 지표, 사용자에게 불필요 |
| 또래 비교 지표 | 삭제 | 비교 스트레스 유발 가능, 코치 메시지로 대체 |
| 8개 KPI 카드 그리드 | 삭제 | 정보 과부하, 코치 메시지 + 여정 + 미션으로 대체 |
| 별도 서류 섹션 | 미션에 통합 | 서류는 "할 일"의 일부, 별도 분리 불필요 |

| 수평 스테퍼 | 세로 여정으로 교체 | 모바일 친화, 상세 정보 표시 용이 |

## 7. 구현 우선순위

| 우선순위 | 항목 | 백엔드 변경 | 예상 시간 |
|---------|------|-----------|----------|
| **P0** | A. AI 코치 히어로 카드 (조건 분기 메시지) | 불필요 | 4h |
| **P0** | B. 세로 여정 지도 (기존 스테퍼 교체) | 불필요 | 3h |
| **P1** | C. 이번 주 미션 (localStorage 체크) | 불필요 | 5h |
| **P1** | D-1. 타임라인 (프론트엔드 localStorage) | 불필요 | 5h |
| **P2** | D-2. 타임라인 (서버 저장 + 동기화) | 필요 | 8h |
| **P2** | A+. AI 코치 메시지 LLM 생성 (RAG) | 필요 | 8h |
| **P3** | C+. 연속 스트릭 + 주간 리포트 | 필요 | 6h |
| **P3** | E. Growth Club 인기 글 인라인 | 필요 | 4h |

### Phase 1: Core Experience (백엔드 변경 없음) — 예상 17h

1. AI 코치 히어로 카드 — 조건 분기 메시지 + 미니 진행 바
2. 세로 여정 지도 — 현재 단계 확장, 완료 단계 날짜
3. 이번 주 미션 — localStorage 체크리스트
4. 타임라인 — localStorage 이벤트 기록

수정 파일:
- `DashboardView.tsx` — 레이아웃 전면 재구성
- `ProgressCard.tsx` → `AiCoachHero.tsx` (교체)
- `RoadmapStepper.tsx` → `JourneyMap.tsx` (교체)
- `WeeklyMission.tsx` (신규)
- `ActivityTimeline.tsx` (신규)
- `GrowthClubCard.tsx` — 타임라인 인라인 버전 추가

### Phase 2: Server Sync + AI Enhancement — 예상 16h

1. 타임라인 서버 저장 (`ActivityEvent` 모델)
2. AI 코치 메시지 LLM 생성 (업종+단계 기반 RAG)
3. Growth Club 인기 글 실시간 연동

### Phase 3: Gamification — 예상 10h

1. 연속 스트릭 (n일 연속 미션 수행)
2. 주간 리포트 (지난주 성과 요약)
3. 마일스톤 축하 애니메이션

## 9. 리스크 평가

| 리스크 | 영향 | 대응 |
|--------|------|------|
| AI 코치 메시지가 반복적으로 느껴질 수 있음 | 사용자 피로 | 메시지 풀을 충분히 확보 (상태 조합 × 변형 3개 이상) |
| localStorage 기반 타임라인 데이터 유실 | 브라우저 초기화 시 히스토리 소실 | Phase 2 서버 동기화로 해결, Phase 1에서는 안내 문구 표시 |
| 세로 여정이 단계가 많을 때 길어짐 | 스크롤 과다 | 완료 단계 접기(collapse) 기능 + "현재 단계로 이동" 앵커 |
| 미션 체크가 실제 진행과 불일치 | 사용자가 체크만 하고 실제 안함 | 운영 관점 리스크 낮음 (셀프 트래킹 목적) |

### 1안 vs 2안 선택 기준

| 상황 | 추천 |
|------|------|
| 데이터 기반 의사결정을 선호하는 운영자/팀 리더 대상 | **1안** |
| 처음 창업하는 비전문가 대상 (StepZero 핵심 타겟) | **2안** |
| AI 차별화를 강조하고 싶을 때 | **2안** |
| 개발 리소스가 제한적일 때 (Phase 1만 할 때) | 비슷 (1안 5h vs 2안 17h) |
| 빠른 MVP 출시가 필요할 때 | **1안** |
| 장기적 사용자 리텐션을 극대화하고 싶을 때 | **2안** |

### 하이브리드 접근 (권장)

두 안의 장점을 결합할 수도 있다:
- **메인 영역**: 2안의 AI 코치 히어로 + 이번 주 미션 (행동 유도)
- **하단 영역**: 1안의 KPI 카드 일부 (총 진행률, 준비도, D-day) 를 축소 배치
- **타임라인**: 2안의 타임라인 (스토리텔링)

이렇게 하면 "코치가 이끌되, 데이터도 볼 수 있는" 균형 잡힌 대시보드가 된다.
