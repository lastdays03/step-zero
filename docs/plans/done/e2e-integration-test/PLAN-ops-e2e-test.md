# PLAN: 운영콘솔 E2E 통합 테스트

> 관리자(superuser) 전용 운영콘솔 기능 브라우저 통합 테스트 (Playwright MCP)

## 목표
- 운영콘솔 8개 영역의 핵심 사용자 플로우를 브라우저에서 검증
- 권한 제어(superuser only), 감사 로그 기록, CRUD 동작 확인
- 일반 사용자 → 접근 차단 시나리오 포함

## 사전 조건
- Backend (port 8000) + Frontend (port 3000) 실행
- 원격 DB/Redis (193.122.102.216) 연결
- `ENABLE_SOCIAL_MOCK=true`
- **superuser 목업 로그인**: `/api/v1/auth/login/social/admin` → `social_admin_user@example.com` (is_superuser=true)
- **일반 유저 목업 로그인**: `/api/v1/auth/login/social/google` → `social_google_user@example.com` (일반 유저)
- 테스트 데이터: 사용자 2명 이상, 그로스클럽 게시글/댓글, ActionKit 아이템 존재

---

## 테스트 시나리오 (총 8개 영역, 30개 케이스)

### Phase 9: 운영콘솔 접근 제어 — 3 케이스
| # | 시나리오 | 검증 포인트 |
|---|---------|------------|
| 9-1 | 일반 사용자 접근 차단 | 일반 유저 로그인 → `/ops` 이동 → 대시보드로 리다이렉트 |
| 9-2 | superuser 접근 허용 | superuser 로그인 → `/ops` → 운영콘솔 홈 메뉴 카드 렌더링 |
| 9-3 | API 직접 호출 차단 | 일반 유저 토큰 → `GET /api/v1/ops/reports/summary` → 403 응답 |

### Phase 10: 서비스 현황 (Reports) — 2 케이스
| # | 시나리오 | 검증 포인트 |
|---|---------|------------|
| 10-1 | 7일 기준 요약 조회 | `/ops/reports` → 활성 사용자, 신규 가입, 로드맵 생성 수 카드 표시 |
| 10-2 | 30일 기간 전환 | 기간 셀렉터 → 30d 선택 → 수치 변경, 전기 대비 delta(%) 표시 |

### Phase 11: 사용자 관리 (Users) — 5 케이스
| # | 시나리오 | 검증 포인트 |
|---|---------|------------|
| 11-1 | 사용자 목록 조회 | `/ops/users` → 사용자 테이블 렌더링, 이메일/상태 컬럼 |
| 11-2 | 검색 필터링 | 검색창에 이메일 입력 → 필터된 결과 표시 |
| 11-3 | 사용자 일시 정지 | 사용자 선택 → 정지 모달 → 사유/기간 입력 → `suspended_temporary` 상태 변경 확인 |
| 11-4 | 사용자 정지 해제 | 정지된 사용자 → `active`로 복원 → 상태 변경 확인 |
| 11-5 | 징계 이력 조회 | 사용자 상세 → 이력 펼치기 → 정지/해제 기록 표시 |

### Phase 12: 공지사항 (Announcements) — 4 케이스
| # | 시나리오 | 검증 포인트 |
|---|---------|------------|
| 12-1 | 공지 목록 조회 | `/ops/announcements` → 공지 리스트, 상태 뱃지(draft/published/archived) |
| 12-2 | 공지 생성 (draft) | 작성 모달 → 제목/내용 입력 → 저장 → 목록에 `draft` 상태로 추가 |
| 12-3 | 공지 발행 | draft 공지 → 발행 버튼 → `published` 상태 변경 → 알림 발송 |
| 12-4 | 공지 보관 | published 공지 → 보관 → `archived` 상태 변경 |

### Phase 13: 감사 로그 (Audit Logs) — 3 케이스
| # | 시나리오 | 검증 포인트 |
|---|---------|------------|
| 13-1 | 로그 목록 조회 | `/ops/audit-logs` → 최근 관리자 작업 로그 테이블 렌더링 |
| 13-2 | 필터 검색 | 액션 타입/대상 타입/날짜 범위 필터 → 결과 갱신 |
| 13-3 | 이전 작업 기록 확인 | Phase 11-3 정지 작업이 감사 로그에 기록되었는지 확인 |

### Phase 14: 그로스클럽 관리 (Growth Club) — 4 케이스
| # | 시나리오 | 검증 포인트 |
|---|---------|------------|
| 14-1 | 대기열 요약 | `/ops/growth-club` → 블라인드 게시글/댓글 건수 뱃지 |
| 14-2 | 블라인드 게시글 목록 | 신고된 게시글 리스트, 신고 횟수/사유 표시 |
| 14-3 | 게시글 블라인드 해제 | 블라인드 게시글 → unblind → 목록에서 제거, 원본 복원 |
| 14-4 | 게시글 영구 삭제 | 블라인드 게시글 → 삭제 확인 → 영구 삭제, 감사 로그 기록 |

### Phase 15: 액션킷 관리 (ActionKit) — 5 케이스
| # | 시나리오 | 검증 포인트 |
|---|---------|------------|
| 15-1 | 대시보드 요약 | `/ops/actionkit` → 아이템/카테고리/파일 수 요약 카드 |
| 15-2 | 카테고리 CRUD | 카테고리 생성 → 이름/슬러그 입력 → 목록 반영 |
| 15-3 | 아이템 상태 변경 | 아이템 선택 → is_active 토글 → 사유 입력 → 상태 변경 + 감사 로그 |
| 15-4 | 파일 업로드 | 아이템 상세 → 파일 첨부 → 업로드 성공 → 파일 목록 반영 |
| 15-5 | 통계 확인 | 통계 탭 → KPI 카드(다운로드 수, 활성 사용자), 인기 아이템 차트 |

### Phase 16: 로드맵 템플릿 (Roadmap Templates) — 4 케이스
| # | 시나리오 | 검증 포인트 |
|---|---------|------------|
| 16-1 | 템플릿 목록 조회 | `/ops/roadmap-templates` → 상태별(draft/approved) 템플릿 테이블 |
| 16-2 | 기존 로드맵에서 템플릿 생성 | 로드맵 검색 → 선택 → 템플릿 생성 → `draft` 상태로 추가 |
| 16-3 | 템플릿 승인 | draft 템플릿 → 승인 버튼 → 사유 입력 → `approved` 상태 변경 |
| 16-4 | 템플릿 상세 편집 | 템플릿 상세 → 단계(step) 추가/순서 변경 → 액션(action) 추가 |

## 실행 순서

```
Phase 9 (접근 제어) → Phase 10 (리포트) → Phase 11 (사용자 관리)
→ Phase 12 (공지사항) → Phase 13 (감사 로그)
→ Phase 14 (그로스클럽 관리) → Phase 15 (액션킷 관리)
→ Phase 16 (로드맵 템플릿)
```

**의존 관계:**
- Phase 13-3은 Phase 11-3 이후 실행 (정지 작업 감사 로그 확인)
- Phase 14-3/14-4는 블라인드 처리된 게시글 데이터 필요
- Phase 16-2는 기존 로드맵 1개 이상 존재 필요

## 스킵 조건
- **전체 Phase 9~16**: superuser 계정 없으면 스킵
- Phase 14: 블라인드 게시글/댓글 없으면 14-2~14-4 스킵
- Phase 16-2: 로드맵 없으면 스킵

## 콘솔 에러 체크
- 모든 Phase에서 페이지 전환 후 `console.error` 없음 확인
- 네트워크 요청 실패(4xx/5xx) 감지
