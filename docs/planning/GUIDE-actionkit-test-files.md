# 📂 액션키트 테스트 파일 가이드 (임시 업로드용)

현재 개발 중인 '관리자 스크린 파일 업로드' 기능을 테스트하기 위해, **가짜(테스트용) 문서 파일**들을 임시로 모아두는 장소와 그 원리에 대한 가이드입니다.

---

## 1. 🗑️ 어디에 테스트 파일을 준비해야 하나요? (준비물 창고)

대표님께서 테스트할 때 마우스로 끌어다 놓을 **PDF나 Word 파일**들을 모아두는 '준비물 창고'입니다. 제가 방금 윈도우 환경에 맞게 폴더를 확실하게 다시 생성해 두었습니다.

*   **폴더 위치 (윈도우 탐색기 창에 복사해서 붙여넣으세요):**
    `c:\Users\User\Desktop\260210최종프로젝트관련자료\test\step-zero\app-backend\tests\fixtures\actionkits`

**👉 대표님이 하실 일:**
아무 내용이나 들어있는 가벼운 PDF, JPG, DOCX 파일 등을 복사해서 위 폴더 안에 3~4개 정도만 툭툭 던져놓아 주세요. (파일명은 알기 쉽게 '테스트_근로계약서.pdf' 등으로 하시면 좋습니다.)

---

## 2. 🕳️ 사이트에서 업로드한 파일은 어디로 가나요? (블랙홀 보관소)

대표님이 브라우저(대시보드 화면)에서 위에서 준비한 파일을 선택해 '업로드' 버튼을 누르면, 백엔드 서버가 그 파일을 삼켜서 보관하는 진짜 '서버의 하드디스크' 위치입니다.

*   **시스템이 파일을 저장할 위치:**
    `test\step-zero\app-backend\data\uploads`

**👉 개발자인 제가 할 일:**
이 `data\uploads` 폴더는 **"절대 팀장님이나 깃허브(GitHub)에 코드를 보낼 때 포함시키지 마라!"** 라는 마법의 투명 망토(`.gitignore` 규칙)를 씌워둘 것입니다. 
따라서 우리는 여기 파일이 100개가 쌓이든 1,000개가 쌓이든 용량이나 보안 걱정 없이 맘 편히 테스트할 수 있습니다. 나중에 프로젝트를 합칠 때는 이 폴더 자체가 쏙 빠진 채로 깨끗하게 전달됩니다. 

---

## 3. 🚀 다음 개발 단계 (진행 중)

현재 이 가이드에 따라 파일이 업로드되었을 때, 
1. 프론트엔드 모달 창에 '파일 드래그 앤 드롭' 상자를 만들고
2. 백엔드에서 파일을 안정적으로 `data\uploads`에 저장하며 버전을 `v1`, `v2`로 자동으로 올리는 코드 작업을 진행하고 있습니다.
