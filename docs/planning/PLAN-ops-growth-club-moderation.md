# PLAN: Ops Growth Club Moderation

## 목표
- 운영콘솔에서 그로스 클럽(커뮤니티) 콘텐츠를 운영자가 안전하게 관리할 수 있는 최소 기능을 구현한다.

## 범위
- 운영콘솔 진입 카드 및 전용 관리 화면
- 게시글/댓글 신고 기반 검토 큐
- 블라인드/해제, 삭제, 신고 처리 상태 관리
- 첨부 파일 점검(파일 존재/경로 정합성) 보조 도구

## 비범위 (이번 단계)
- 자동 심사(ML/NLP) 도입
- 외부 스팸 탐지 서비스 연동
- 사용자 제재(정지/차단) 고도화 정책

## 운영 정책 초안
- 신고 누적 기준 자동 블라인드는 유지하되, 운영자가 수동 해제 가능
- 운영자 조치는 반드시 사유(reason)를 남긴다
- 삭제는 소프트 삭제 우선, 파일 정리는 백그라운드 정리 작업으로 분리 가능

- [o] 5. 댓글 블라인드/해제 API 추가
- [] 6. 운영 조치 이력(누가/언제/무엇을) 최소 로그 남기기
- [ ] 7. 첨부 파일 경로 점검 유틸(존재 여부) 제공
- [ ] 8. 화면 로딩/빈 상태/오류 상태 명확화

## 현재 구현 상태 메모
- `Ops` 메인 카드 및 `/ops/growth-club` 라우트/기본 페이지는 반영 완료
- 본 플랜의 남은 범위는 운영 API/조치 UX/감사로그 연동 중심

## API 네임스페이스 기준
- 운영 API는 `/api/v1/ops/*` 기준으로 구현한다.
- 사용자 커뮤니티 API(`/api/v1/growth-club/*`, `/api/v1/community/*`)와 분리 유지한다.

## 데이터/API 설계 메모
- 조회 단위:
  - `reported_posts`: 신고수, 작성자, 작성시각, 상태
  - `reported_comments`: 신고수, 작성자, 작성시각, 상태, 상위 게시글
- 조치 단위:
  - `action`: `BLIND | UNBLIND | DELETE`
  - `target`: `POST | COMMENT`
  - `reason`: string (required)

## 구현 순서 제안
1. 감사로그 기록 인프라(테이블/유틸) 선반영 여부 확인
2. 읽기 API(신고 목록) + 화면 조회
3. 조치 API(블라인드/해제) + 화면 액션 버튼
4. 운영 로그/파일 점검 보강

## 구현 게이트
- 블라인드/해제/삭제 조치 API는 감사로그 연동 없이 배포하지 않는다.

## 완료 기준 (DoD)
- 운영자가 `/ops/growth-club`에서 신고 대상 조회 및 블라인드/해제를 수행할 수 있다.
- 조치 후 목록이 즉시 갱신되고, 빈/오류 상태가 UX로 구분된다.
- 기능 변경에 대한 최소 테스트/린트가 통과한다.
