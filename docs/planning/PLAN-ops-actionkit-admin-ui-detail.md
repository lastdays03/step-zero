# 👑 관리자용 API 개발이란? (클라이언트 설명용 비유 가이드)

본 문서는 `/ops` 관리자 스크린(어드민) 구축 작업을 클라이언트나 비개발 직군이 한눈에 파악할 수 있도록 작성된 백서입니다.

---

## 🍽️ 1. API란 무엇인가요? (레스토랑의 '웨이터')

상상해 보세요. 우리가 방금 예쁘게 만든 '법령 가이드'와 '액션 키트' 화면은 깔끔하게 세팅된 **레스토랑의 식사 테이블(프론트엔드)**이에요.
식재료와 진짜 레시피는 시크릿한 **주방(데이터베이스)**에 보관되어 있죠.
이때 식사 테이블(화면)에서 "새로운 메뉴 주세요!"라고 주문을 하면, 그 주문서를 주방장에게 전달하고 요리된 음식을 다시 테이블로 가져다주는 **'웨이터(심부름꾼)' 역할**을 하는 것이 바로 **API**입니다.

## 🎮 2. 관리자용(Ops) API 개발은 왜 필요한가요? (마법의 전용 리모컨 만들기)

지금까지는 새로운 문서나 체크리스트를 추가하려면 개발자가 직접 '주방(코드)'에 들어가서 타자를 쳐야만 했어요. 코드를 모르는 일반 직원은 아무것도 건드릴 수가 없었죠.
하지만 서비스가 진짜로 돌아가려면, 클라이언트(대표님이나 운영팀)께서 개발자를 부르지 않고도 직접 마우스 클릭 몇 번으로 쉽게 내용을 바꾸고 파일을 올릴 수 있어야 합니다.

그래서 이번 단계에서는 **"아무나 부를 수 없는, 매니저(운영자) 전용 똑똑한 웨이터(API)"**를 만드는 작업을 할 겁니다. 기획서에 있는 복잡한 영어들을 쉬운 말로 바꾸면 이렇습니다:

*   **목록 보기 (GET API):** *"현재 우리 서랍(서버)에 어떤 법률 문서들이 올라가 있는지 목록 좀 쫙 보여줘!"* 라고 웨이터에게 시키는 기능이에요. (검색 기능 포함)
*   **내용 수정하기 (PATCH API):** *"여기 '근로계약서' 부분에 오타가 났네. 몰래 제목만 슥 바꿔놔!"* 라고 명령하면 웨이터가 즉시 고쳐놓는 수리 기능이에요.
*   **파일 업로드/버전 관리 (File API):** 파일이 법 개정으로 바뀌었을 때, *"옛날 문서 기록은 안 보이게 서랍장 밑에 놔두고, 방금 내가 새로 올린 파일을 '최신 버전' 명찰을 붙여서 사람들이 가져가게 해!"* 라고 똑똑하게 문서를 업데이트해 주는 아주 중요한 심부름꾼입니다.
*   **안전장치 및 CCTV (감사로그 탑재):** 아무나 주방에 들어와서 레시피를 망치면 안 되잖아요? 그래서 **'진짜 관리자 명찰'**을 단 사람만 이 행동들을 할 수 있게 잠금장치를 만들고, 누가 언제 무슨 문서를 지우고 바꿨는지 **블랙박스(CCTV 장부)**에 꼼꼼히 적어두는 안전 기능까지 같이 만듭니다.

## 💻 3. 관리자 스크린 단계는 어떤 부분을 만드나요?

지금까지 우리는 고객들이 문서를 보고 다운받는 '손님용 테이블(서비스 화면)'을 아주 예쁘게 꾸몄습니다. 이제부터는 **사장님(운영자)이 가게 장부를 편하게 보며 내용물을 쑥쑥 채워넣고 수정할 수 있는 '비밀번호 걸린 사장님 전용 사무실(관리자 스크린)'**을 인테리어 하는 설계도입니다.

우리가 만들어야 할 **가장 중요한 방(화면)**은 크게 **두 가지**입니다.

### 📊 "한눈에 쫙! 대시보드" (목록/검색 화면)
*   **어떤 화면인가요?:** 어지러운 서류 더미를 깔끔한 '엑셀 표'처럼 쫙 펼쳐놓는 큰 화면입니다.
*   **핵심 기능:**
    *   **탭 나누기:** "법령 가이드" 서류와 "실무 액션키트" 서류를 버튼 하나로 분류해서 볼 수 있어요.
    *   **서류 찾기:** 수백 개의 문서 중 "근로계약서"라고 치면 바로 튀어나오게 검색창을 달고, 현재 사용자들에게 **'공개 중'인지 '숨김' 상태인지** 한눈에 분류하는 필터가 들어갑니다.

### 📝 "클릭 한 번으로 요리조리 수정!" (상세 정보 ＆ 파일 업로드 화면)
*   **어떤 화면인가요?:** 앞서 표에서 한 서류를 콕 집어 클릭하면 들어가는 자세한 정보 화면입니다.
*   **핵심 기능:**
    *   **이름표 갈아끼우기 (메타데이터 편집):** "앗, 이 문서 제목이 별로네? 요약 설명도 좀 더 친절하게 바꿔야지." 라고 마음먹었다면, 개발자를 부를 필요 없이 화면에서 바로 글씨를 타이핑해서 '저장'만 누르면 손님용 화면에 실시간으로 짠! 하고 반영됩니다.
    *   **새 파일 갈아 끼우기 (업로드 버튼):** 법이 바뀌어서 옛날 PDF 파일을 새 PDF 파일로 엎어야 할 때, 바탕화면에 있는 **파일을 마우스로 쭉 끌어서(드래그) 이 화면에 떨어뜨리기만 하면** 알아서 "2025년 최신 버전"으로 척척 교체됩니다. 사용자들은 알아서 갱신된 최신 파일만 받아가게 되죠.
    *   **실수 방지 안전망 (버전 히스토리 기록장):** 직원이 실수로 이상한 걸 올렸다고요? 걱정 마세요. "어제 홍길동 주임이 올린 기록", "한 달 전에 올렸던 원본 기록"이 화면 밑에 주르륵 남습니다.

## 🗺️ 4. (프론트/백엔드) 개발 로드맵 단계

**1. 입장 권한 철통 방어기 (진입 단계)**
*   가장 먼저 할 일은 "권한을 확인 중입니다"에서 넘어갔을 때, **일반 회원이면 아예 들어오지 못하게(접근 거부/차단) 문을 단단히 걸어 잠그는(Auth Guard)** 작업입니다.

**2. 통제 센터 뼈대 만들기 (백엔드 API 세팅 단계)**
*   프론트엔드 화면을 그리기 전에, 백엔드에서 필요한 정보를 줄 전용 '웨이터(API)'들을 먼저 만들어야 합니다.
*   **전용 탭:** `법령 가이드`와 `액션키트`를 나눠서 쏴줄 조회 기능.
*   **검색 및 필터:** "근로계약서" 검색어 등을 처리할 수 있는 기능.
*   **문서 편집 및 버전 관리:** 새로운 PDF나 문서를 받았을 때 "기존 것은 v1으로 내리고, 새것을 v2 최신 배지로 달아라!" 라고 명령을 처리할 코어 기능 개발.

**3. 사장님 대시보드 그리기 (프론트엔드 UI 화면)**
*   **목록 뷰 (List View):** 현재 서비스 중인 모든 문서를 엑셀 리스트처럼 시원하게 보여주는 관리자 표(Table)를 만듭니다. '게시 중(초록 불)' / '중단(빨간 불)' 상태를 직관적으로 보이게 합니다.
*   **상세 및 수정 창 (Detail Modal/Page):** 특정 문서를 꾹 누르면 열리는 수정 창을 만듭니다. 여기서 소개글도 고치고, 태그도 다시 달 수 있습니다.
*   **업로드 존 (Upload Zone):** 마우스로 파일을 쭉- 끌어다 놓기만 해도 구 버전과 신 버전을 척척 교체하고 완료 알림(토스트) 팝업을 띄우는 편안한 UX를 적용합니다.

**4. 블랙박스 기록 연동 (안전망 단계)**
*   "A 직원이 2월 23일에 1번 문서를 수정함"과 같은 **감사 로그(Audit Log)**가 반드시 자동으로 서버에 찍히도록 안전장치를 마지막으로 점검합니다.
