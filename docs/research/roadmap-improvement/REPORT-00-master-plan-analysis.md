## 2. 코드베이스 vs 마스터 플랜 대조

### Phase 1 (Week 1-3) - FE Only, 비용 제로

| 작업 | 대상 파일 | 현재 상태 | 난이도 |
|------|----------|----------|--------|
| Endowed Progress UI | `RoadmapExecutionView.tsx` (114줄), `RoadmapSidebar.tsx` (113줄) | 컴포넌트 존재, 프로그레스 바 있음. 17% 시작점 로직만 추가 | **쉬움** |
| 다음 3-5 액션 집중 | `TimelineStepItem.tsx` (307줄) | 액션 렌더링 로직 있음. 접기/펼치기 추가 | **쉬움** |
| 준비도 5단계 스코어 | `RoadmapSidebar.tsx`, `RoadmapStepper.tsx` (137줄) | 진행률 % 표시 중. 5단계 등급 매핑 추가 | **보통** |
| 마일스톤 축하 | `TimelinePhaseCard.tsx` (238줄) | Phase 상태관리 있음. 축하 모달/컨페티 추가 | **보통** |
| 첫 5분 최적화 | `RoadmapChatIntake.tsx` (437줄) | 6단계 인터뷰 완성됨. 실시간 확인 표시 추가 | **보통** |

**결론: Phase 1은 모든 컴포넌트가 이미 존재. 기존 코드 위에 UX 개선만 얹는 구조로, 3주 일정 현실적.**

### Phase 2 (Week 4-8) - AI 코치 + 리텐션

| 작업 | 기존 인프라 | 신규 필요 | 리스크 |
|------|-----------|----------|--------|
| AI 코치 BE | ChatService, RagService, SemanticRouter 존재 | RoadmapContextBuilder, SSE 라우터, DB 2개 테이블 | **중** - SSE 스트리밍 기존 코드에 없음 (30% 재활용) |
| AI 코치 FE | ChatPanel/ChatInput 컴포넌트 존재 | StepChatPanel, useStepChat hook | **중** - 스트리밍 UI 신규 |
| 알림 인프라 | Notification 모델/API 존재 | cron job, 이메일 템플릿, 카카오톡 API | **높음** - 외부 서비스 연동 |
| 주간 이메일 | 없음 | 전체 신규 | **높음** |
| 카카오톡 알림톡 | 없음 | 비즈 채널 + API 전체 신규 | **높음** |

**코드 재활용 논쟁 주의** (마스터 플랜 부록 B):
- 낙관: 78% 재활용, 2-3주
- 보수: 20-25% 재활용, 4-6주
- 문서는 낙관 채택 + 2주 버퍼. **실질적으로 Phase 2가 가장 리스크 높음.**

### Phase 3 (Week 9-16) - 법령 변경 알림

| 작업 | 실현 가능성 | 비고 |
|------|-----------|------|

| K-Startup API 연동 | 외부 API 안정성 미검증 | Kill Switch 있음 |

## 3. 전략적 강점

1. **팩트-지능 분리 아키텍처** - ActionKit DB가 hallucination 방지의 물리적 장벽. Harvey AI 0.2% 환각률 패턴과 동일
2. **ChatGPT 구조적 불가 영역 3가지** - 세션 비영속, 법령 모니터링 없음, 개인 로드맵 추적 불가. 이건 진짜 해자
3. **Phase 1 비용 제로** - FE만으로 UX 개선 -> 빠른 검증 -> Go/No-Go 판단
4. **한국 시장 공백** - AI 기반 개인화 창업 가이드 제공 한국 제품 부재 (소상공인마당=정보 나열, 뤼튼=범용)

### 최고 우선 (블로커)

| 리스크 | 문서 내 대응 | 평가 |

### 높음 (일정 리스크)

| 리스크 | 평가 |
|--------|------|
| **Phase 2 일정** | 코드 재활용률 논쟁 (20% vs 78%). SSE 스트리밍이 기존 코드에 없어 신규 구현 비중 높음. 5주 -> 7주 될 가능성 |
| **카카오톡 알림톡** | 비즈 채널 신청 + 템플릿 검수 + KISA 규정. 기술보다 행정 절차가 병목 |
| **ActionKit 8개 업종 한계** | IT/이커머스 fallback 시 즉각 이탈 경고. 업종 확대 일정 없음 |

### 보통 (모니터링)

| 리스크 | 평가 |
|--------|------|
| MRR 2,000만원 목표 | Q4 기준 Free 15,000명 x 8% = 1,200명 유료. 현실적이려면 월 ~16,700원 ARPU 필요 |
| 구독 피로 | 일회성 99,000원 옵션 병행 제안은 좋으나 미해결 쟁점으로 남아있음 |

## 7. 실행 권장 순서

```
즉시 (Phase 1 시작 전)
+-- 법률 자문 착수 (변호사법 + AI 기본법) <- Phase 2 블로커
+-- 이벤트 트래킹 인프라 설치 <- Go/No-Go 측정 필수
+-- 카카오톡 비즈 채널 신청 <- 행정 리드타임 2-4주

Phase 1 (Week 1-3) <- 계획대로 진행 가능
+-- Sprint 1-A: Endowed Progress + 액션 집중
+-- Sprint 1-B: 준비도 스코어 + 마일스톤 + 첫 5분

Go/No-Go 판단 (Week 3 말)
+-- 첫 단계 진입율 >= 40%?
+-- 초기 이탈률 < 60%?

Phase 2 (Week 4-8+) <- 2주 버퍼 확보 권장
+-- AI 코치 BE -> FE -> 알림 -> 스트릭
```

## 8. 종합 평가

### 문서 품질: 상

- 17개 기능을 Impact/Effort로 명확히 분류
- Phase별 Go/No-Go 기준이 정량적
- Must-Not-Do 목록으로 스코프 크리프 방지
- 벤치마크 근거가 구체적 (Harvey AI, Duolingo, LinkedIn 등)

### 실현 가능성: 중상

- Phase 1: 높음 (기존 코드 위에 UX 개선)
- Phase 2: 중 (SSE 스트리밍 + 외부 서비스 연동 리스크)
- Phase 3: 중 (ActionKit 역추적은 가능, K-Startup API는 미검증)

### 최대 리스크: Phase 2 일정

- AI 코치 MVP 코드 재활용률 논쟁 (20% vs 78%)이 일정에 직접 영향
- SSE 스트리밍이 기존 코드에 없어 신규 구현 비중 높음
- 법률 자문이 Phase 2 착수 전 완료되지 않으면 전체 일정 지연
