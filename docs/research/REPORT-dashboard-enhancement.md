# StepZero 대시보드 개선 보고서

> 작성일: 2026-03-04

## 1. 현재 상태 분석

### 1.1 스크린샷 기반 UI 현황

현재 대시보드는 5개 영역으로 구성되어 있다:

```
┌─────────────────────────────────────────────────────────┐
│ 인사말 헤더 ("좋은 아침입니다, 박종만님")         🔔     │
├────────────────────────────────┬────────────────────────┤
│ 현재 진행 단계 카드             │ Growth Club 카드       │
│ 영업 인허가 / 75% / D-28       │ 12명 동료 창업자       │
│ [신청 계속하기 →]               │                        │
├────────────────────────────────┴────────────────────────┤
│ 나의 로드맵 (스텝 1개만 표시)            [전체 계획 보기]│
├──────────────────┬──────────────┬───────────────────────┤
│ 필요 서류 (2건)   │ 28일 남음    │ 0/1 작업 완료율       │
└──────────────────┴──────────────┴───────────────────────┘
                                    [StepZero AI에게 물어보기]
```

### 1.2 백엔드 데이터 구조

현재 API 응답 (`GET /api/v1/dashboard`):

```json
{
  "user_name": "박종만",
  "current_phase": { "title": "영업 인허가", "progress": 75, "status": "IN_PROGRESS" },
  "roadmap": [
    { "title": "Phase 1", "status": "completed", "date": "" },
    { "title": "Phase 2", "status": "current", "date": "" },
    { "title": "Phase 3", "status": "locked", "date": "" }
  ],
  "stats": { "days_left": 28, "tasks_completed": 0, "total_tasks": 1 },
  "growth_club": { "founders_online": 12 }
}
```

### 1.3 핵심 문제점

| # | 문제 | 영향 | 심각도 |
|---|------|------|--------|
| 1 | **정보 밀도 부족** — 5개 카드에 담긴 정보가 절대적으로 적음 | 사용자가 대시보드에서 얻는 가치가 낮아 재방문 동기 부족 | 높음 |
| 2 | **로드맵 스테퍼가 1개 단계만 표시** — 전체 여정 조감이 불가능 | 진행 감각 상실, "어디까지 왔고 얼마나 남았는지" 파악 불가 | 높음 |
| 3 | **Growth Club 데이터 하드코딩** — 항상 12명 고정 | 라이브 느낌 없이 정적, 커뮤니티 참여 유도 실패 | 중간 |
| 4 | **개인화 부재** — 인사말 외 맞춤 콘텐츠 없음 | 모든 사용자에게 동일한 화면, 차별화된 가치 제공 불가 | 높음 |
| 5 | **다음 행동 불명확** — "신청 계속하기"만 존재 | 사용자가 "지금 뭘 해야 하는지" 즉시 파악 어려움 | 높음 |
| 6 | **진척도 맥락 부재** — 75%라는 숫자만 표시 | "75%가 좋은 건지, 빠른 건지, 느린 건지" 판단 불가 | 중간 |
| 7 | **서류 섹션이 다운로드 목록에 그침** — 상태 추적 없음 | 어떤 서류를 준비했고 어떤 걸 아직 못했는지 모름 | 중간 |
| 8 | **마감 카운트다운 맥락 부족** — "28일"만 표시 | 긴급도 인식 어려움, 마감 대비 진행률 상관관계 미표시 | 낮음 |

### 2.2 영역별 상세 개선안

#### A. 컨텍스트 인사말 (Context-Aware Greeting)

**현재**: "좋은 아침입니다, 박종만님. 오늘 귀하의 비즈니스를 공식적으로 등록해 봅시다."
**문제**: 인사말은 개인화되었으나 부제가 일반적. 현재 진행 상태와 무관한 정적 문구.

**개선안**:
```
시간대별 인사 + 현재 단계 컨텍스트 + 오늘의 할 일 개수

"좋은 아침입니다, 박종만님!"
"영업 인허가 단계를 진행 중이에요. 오늘의 할 일 1건이 있어요."
```

| 상태 | 부제 예시 |
|------|----------|
| 로드맵 없음 | "AI가 맞춤 창업 로드맵을 만들어 드릴게요." |
| 첫 단계 진행 중 | "첫 단계를 시작하셨네요! 서류 준비부터 시작해 볼까요?" |
| 중간 단계 | "영업 인허가 단계를 진행 중이에요. 오늘의 할 일 1건이 있어요." |
| 마감 임박 (D-7 이하) | "마감까지 7일 남았어요. 남은 서류 2건을 마무리해 주세요!" |
| 단계 막 완료 | "🎉 영업 인허가 단계를 완료했어요! 다음 단계를 확인해 보세요." |
| 전체 완료 | "🚀 모든 준비가 끝났어요! 사업 시작을 축하합니다!" |

**구현 범위**: 프론트엔드 로직만 (백엔드 변경 불필요, 기존 데이터로 분기 가능)

---

#### B. 로드맵 타임라인 강화 (Full Journey View)

**현재**: 스테퍼에 1개 단계만 표시 — 전체 여정이 보이지 않음
**문제**: 사용자가 "어디까지 왔고, 얼마나 남았는지" 한눈에 파악 불가

**개선안**:
- 전체 단계를 수평 타임라인으로 항상 표시 (현재 코드에는 이미 구현되어 있으나 데이터가 부족할 때 1개만 나옴)
- 각 단계에 예상 소요일/실제 소요일 표시
- 완료 단계는 실제 완료 날짜 표시
- 현재 단계에 진행률 미니 바 표시

```
[1 사업계획] ── [2 임대차] ── ● 3 영업 인허가 ── [4 세무] ── [5 팀 구성]
  ✅ 완료         ✅ 완료       🔵 75%             🔒           🔒
  2/15 완료       2/20 완료     진행 중             대기          대기
```

**백엔드 변경 필요**:
- `RoadmapItem`에 `completed_at: str | None` 필드 추가
- `DashboardService`에서 각 phase의 완료 날짜 계산 로직 추가

---

#### C. "오늘의 할 일" 섹션 신설 (Today's Actions)

**현재**: 없음. "신청 계속하기" 버튼만 존재.
**문제**: 사용자가 "지금 당장 뭘 해야 하는지" 명확히 알 수 없음

**개선안**:
현재 단계의 미완료 액션을 우선순위별로 정렬하여 체크리스트로 표시

```
📋 오늘의 할 일

☐ 통신판매업 신고서 제출
  📎 전자상거래법 양식 필요  ·  ⏰ 예상 3일  ·  [서류 다운로드]

☐ 영업신고증 발급 신청
  📎 영업인허가 양식 필요  ·  ⏰ 예상 5일  ·  [가이드 보기]
```

**데이터 소스**: 이미 `RoadmapStepDetail`에 액션 데이터가 있음. 현재 단계의 `actions` 중 `completed=false`인 항목을 추출하면 됨.

**백엔드 변경 필요**:
- Dashboard 응답에 `today_actions: list[ActionItem]` 필드 추가
- `ActionItem`: `{ title, description, action_type, estimated_days, document_name?, is_completed }`
- 기존 `RoadmapStepDetail.actions`에서 현재 단계 것만 필터링

#### D. 서류 체크리스트 (Document Checklist with Status)

**현재**: 서류 이름 + "필수" 뱃지 + 다운로드 버튼만 표시
**문제**: 어떤 서류를 이미 준비했는지, 어떤 게 남았는지 추적 불가

**개선안**:
```
📄 필요 서류                                    1/4 완료

✅ 사업자등록증 ──────────────────── 완료 (2/15)
☐ 전자상거래법 ──────────── 필수 ── [다운로드]
☐ 전자상거래법 시행령 ───── 필수 ── [다운로드]
☐ 통신판매업 신고서 ─────────────── [양식 받기]

진행: ████░░░░░░░░ 1/4
```

**구현 방식 2가지**:

| 방식 | 장점 | 단점 |
|------|------|------|
| **A. 로컬 상태** (localStorage) | 백엔드 변경 없음, 즉시 구현 | 기기 간 동기화 불가 |
| **B. 서버 상태** (DB) | 영구 저장, 팀원 공유 가능 | 새 API + DB 컬럼 필요 |

**권장**: Phase 1에서 방식 A (localStorage)로 빠르게 구현, Phase 2에서 B로 전환

#### E. 창업 현황 대시보드 (My Startup Status)

**현재**: "28일 남음"과 "0/1 완료율" — 숫자 2개만 표시
**문제**: 맥락 없는 숫자는 의미 전달이 약함

**개선안**:
```
📊 나의 창업 현황

진행률      ████████░░░░ 75%
남은 일수    D-28 (여유)
완료 단계    2 / 4 단계
준비도      ✅ 인허가 완료

── 또래 비교 ──────────────
비슷한 업종 창업자 대비
🟢 상위 30% 속도
평균 완료 기간: 45일
```

**추가 지표 후보**:

| 지표 | 설명 | 데이터 소스 | 구현 난이도 |
|------|------|------------|-----------|
| 완료 단계 수 | 전체 중 몇 단계 완료했는지 | 기존 `roadmap[]` 데이터 | 낮음 |
| 준비도 레벨 | 이미 구현된 readiness label | 기존 `computeReadinessLevel()` | 낮음 (이미 있음) |
| 마감 긴급도 색상 | D-7 이하 빨간색, D-14 이하 노란색 | 기존 `days_left` | 낮음 |
| 또래 비교 | 같은 업종 창업자 평균 대비 속도 | 새 집계 쿼리 필요 | 높음 |
| 주간 활동량 | 이번 주 완료한 작업 수 | 새 이벤트 로깅 필요 | 높음 |

#### F. Growth Club 카드 강화

**현재**: "12명의 동료 창업자와 실시간으로 소통하기" — 하드코딩, 클릭 유도 약함
**문제**: 실시간 데이터 아님, 커뮤니티 참여를 유도할 구체적 콘텐츠 없음

**개선안**:
```
💬 Growth Club                    🟢 12명 온라인

최근 인기 글:
📌 "카페 창업 인허가 빨리 받는 팁 공유"  👍 23
📌 "세무사 선택 기준 추천해요"          👍 18

비슷한 단계 창업자:
👤 김OO (카페, 영업 인허가 단계)
👤 이OO (레스토랑, 영업 인허가 단계)

                          [커뮤니티 방문하기 →]
```

**백엔드 변경 필요**:
- `growth_club` 응답 확장:
  ```json
  {
    "founders_online": 12,        // 실시간 (Phase 2)
    "trending_posts": [           // 최근 인기 게시글 2~3건
      { "title": "...", "like_count": 23 }
    ],
    "similar_founders": [         // 같은 단계 창업자 (익명)
      { "display_name": "김OO", "business_type": "카페", "phase": "영업 인허가" }
    ]
  }
  ```
- `trending_posts`: `GrowthClubPost` 최근 7일 좋아요 상위 3건 — 쿼리 추가 (간단)
- `similar_founders`: 같은 phase 진행 중인 사용자 수 집계 — 프라이버시 주의

#### G. AI 추천 팁 섹션 (Contextual AI Tips)

**현재**: 없음 (AI 챗봇 FAB만 존재)
**문제**: AI 기능의 가치가 대시보드에서 드러나지 않음. 사용자가 먼저 질문해야만 가치를 경험.

**개선안**:
```
💡 AI 추천 팁

"영업 인허가 단계에서는 관할 구청에 직접 방문하는 것이
 온라인 신청보다 평균 3일 빠릅니다."

                                   [자세히 보기] [다른 팁]
```

**구현 방식**:

| 방식 | 설명 | 장점 | 단점 |
|------|------|------|------|
| **A. 사전 생성 팁 DB** | 각 phase별 팁 5~10개 사전 작성 | API 호출 없음, 빠름 | 개인화 부족 |
| **B. RAG 기반 동적 팁** | 현재 단계 + 업종으로 RAG 검색 | 고도로 개인화 | LLM 호출 비용, 지연 |
| **C. 하이브리드** | 기본 팁 DB + 주 1회 LLM 생성 | 균형 잡힌 접근 | 구현 복잡도 중간 |

**권장**: Phase 1에서 방식 A (phase별 정적 팁), Phase 2에서 C로 확장

### 2.3 마이크로인터랙션 및 UX 개선

#### H. 마일스톤 축하 (Milestone Celebrations)

**현재**: readiness level 변경 시 토스트 알림만 (5초)
**개선안**:
- 단계 완료 시 confetti 애니메이션 + 축하 모달
- "다음 단계 미리보기" CTA 포함
- 소셜 공유 버튼 (선택적)

#### I. 마감 긴급도 시각화

**현재**: "28일" 텍스트만
**개선안**:
```
D-28 이상:  🟢 여유 (녹색 텍스트)
D-14~27:   🟡 주의 (노란색 텍스트 + 아이콘)
D-7 이하:   🔴 긴급 (빨간색 + 펄스 애니메이션)
D-0:        ⚫ 마감 (회색 + "기한 연장 문의" 링크)
```

#### J. 빈 상태(Empty State) 개선

**현재**: 로드맵 1단계만 있을 때 스테퍼가 허전함
**개선안**:
- 단계가 적을 때 "더 자세한 로드맵이 필요하신가요?" CTA 표시
- AI에게 로드맵 세분화 요청 유도
- 빈 영역에 업종 관련 일러스트레이션 또는 통계 표시

## 6. 경쟁 서비스 벤치마크

| 기능 | StepZero (현재) | Notion 프로젝트 | Linear | Stripe Atlas |

| 진행률 시각화 | ○ (원형 차트) | ○ (프로그레스 바) | ◎ (번다운 차트) | ◎ (단계별 체크) |
| 다음 행동 안내 | △ (버튼 1개) | ○ (할 일 목록) | ◎ (우선순위 큐) | ◎ (단계별 가이드) |

## 7. 결론

현재 대시보드는 **기능적으로 작동하지만 정보 밀도와 행동 유도력이 부족**하다. 사용자가 대시보드를 열었을 때 "지금 뭘 해야 하는지"를 3초 안에 파악할 수 있어야 하며, 진행 상황에 대한 성취감과 다음 행동에 대한 명확한 안내가 필요하다.

**핵심 개선 방향 3가지**:
1. **행동 중심** — "오늘의 할 일"로 즉각적인 행동 유도
2. **맥락 제공** — 숫자에 의미를 부여 (긴급도, 또래 비교, 준비도 레벨)
3. **AI 가치 노출** — 챗봇을 기다리지 말고, 대시보드에서 먼저 AI 인사이트 제공

Phase 1 (Quick Wins)만으로도 체감 개선이 크므로, 백엔드 변경 없이 프론트엔드만 수정하는 것부터 시작하는 것을 권장한다.
