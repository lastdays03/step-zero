# Project Report Generator

Generate a professional project status report for external audiences. Unlike the health check (internal/technical), this report emphasizes accomplishments, architecture decisions, and forward-looking roadmap.

## When to Use

- Sharing progress with stakeholders or investors
- Sprint/milestone retrospective documentation
- Team onboarding documentation
- Portfolio/showcase material
- When someone asks "what does this project do and where is it?"

## Report Generation Process

### Step 1: Gather Context

Read these sources (in parallel where possible):

**Project Identity**
- `CLAUDE.md` or `README.md` — project overview, tech stack
- `package.json` / `pyproject.toml` — version, dependencies count

**Development History**
- `git log --oneline --since="30 days ago"` — recent activity
- `git log --oneline --all | wc -l` — total commits
- `git shortlog -sn --no-merges | head -5` — contributors

**Completed Work**
- `docs/plans/done/` — archived completed features
- `docs/context/dev-status.md` — current state
- `docs/context/decisions.md` — key architectural decisions

**Scale Metrics**
```bash
# Lines of code (approximate)
find app-backend/app -name "*.py" | xargs wc -l 2>/dev/null | tail -1
find app-frontend/src -name "*.ts" -o -name "*.tsx" | xargs wc -l 2>/dev/null | tail -1

# Test count
cd app-backend && uv run pytest --collect-only -q 2>&1 | tail -1

# API endpoints
grep -r "@router\." app-backend/app/api/ --include="*.py" | wc -l
```

**Active Work**
- `docs/plans/active/` — in-progress features
- Open PRs: `gh pr list --state open 2>/dev/null`

### Step 2: Compose Report

Save to `docs/plans/reports/REPORT-project-status-{YYYY-MM-DD}.md` using this structure:

```markdown
# {Project Name} — Project Status Report

> **Date:** {date}
> **Version:** {version}
> **Period:** {date range or "as of {date}"}

---

## Executive Summary

{2-3 sentences: what the project is, current phase, key highlight}

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Backend | {e.g., FastAPI, PostgreSQL, Redis} |
| Frontend | {e.g., Next.js, React, Tailwind CSS} |
| Infrastructure | {e.g., Docker Compose, ARQ Worker} |
| AI/ML | {e.g., OpenAI, PGVector, RAG} |

## Key Metrics

| Metric | Value |
|--------|-------|
| Backend LoC | {lines} |
| Frontend LoC | {lines} |
| API Endpoints | {count} |
| Test Cases | {count} passed |
| Total Commits | {count} |
| Contributors | {count} |

## Features Delivered

{List completed features with brief descriptions. Group by domain/milestone if many.}

### {Feature Group 1}
- **{Feature Name}** — {1-line description}
- **{Feature Name}** — {1-line description}

### {Feature Group 2}
- ...

## Architecture Highlights

{2-3 key architectural decisions that define the system. Reference decisions.md if available.}

## Current Sprint / In Progress

{What's being worked on now. Keep brief.}

- {Task 1} — {status}
- {Task 2} — {status}

## Roadmap

{What's planned next. If docs/plans/ has future plans, reference them.}

| Priority | Item | Status |
|----------|------|--------|
| P0 | {item} | {planned/in-progress} |
| P1 | {item} | {planned} |
| P2 | {item} | {planned} |

## Risks & Dependencies

{Any blockers, external dependencies, or technical risks worth noting}

*Generated by Claude Code on {date}*
```

## Key Principles

- **Audience-aware**: This report goes to non-engineers too. Minimize jargon. "AI-powered legal guidance chatbot" is better than "RAG pipeline with semantic routing over PGVector embeddings".
- **Achievement-focused**: Lead with what's done, not what's broken. Health check covers problems; this covers progress.
- **Quantify where possible**: "Built 45 API endpoints" is more impressive than "built many endpoints". Numbers ground the report.
- **Honest about risks**: Don't hide problems, but frame them constructively. "Database migration pending for production deploy" not "production is broken".
- **Visual structure**: Use tables and lists liberally. Dense paragraphs lose readers.
- **Concise**: The entire report should be scannable in 2 minutes. If a section runs long, it probably needs to be summarized or moved to an appendix.
