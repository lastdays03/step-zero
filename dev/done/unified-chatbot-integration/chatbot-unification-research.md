## 1. 현재 구현 상태 (통합 이후)

기술적으로는 단일 SSE 엔드포인트(`POST /rag/chat/stream`)로 통합되었으나, **UX 관점에서는 여전히 두 모드가 분리**되어 있음.

| 구분 | AI 어시스턴트 (일반) | AI 코치 (로드맵) |
|------|---------------------|-----------------|
| 헤더 | "AI 어시스턴트" | "AI 코치 · {단계명}" |
| 빈 상태 | "무엇이든 물어보세요!" | "현재 단계에 대해 물어보세요" |
| 대화 이력 | **저장 안 함 (휘발)** | DB 저장 + 재방문 시 복구 |
| 출처 인용 | 없음 | [법령 N], [서류 N] |
| 진입 방식 | FAB 클릭 | 로드맵 "AI 코치" 버튼 |
| 모드 전환 | 수동 불가 | TimelineStepItem에서만 |

## 2. 로드맵별 대화 이력 저장의 이점 분석

### 2.1 이점

#### 컨텍스트 연속성
- 사용자가 "사업자등록 어떻게 해요?"라고 물은 뒤, 며칠 뒤 "그래서 서류는 어디서 발급받아?"라고 하면 — 이력이 있어야 **"그래서"가 뭘 가리키는지** AI가 파악 가능
- 이력 없으면 매번 처음부터 다시 설명해야 함

#### 단계별 맥락 분리
- 카페 창업 로드맵 예시:
  - 1단계(사업자등록) 대화: 세무서, 업종코드 관련 질문들
  - 2단계(영업신고) 대화: 위생교육, 보건소 관련 질문들
- **하나의 스레드에 다 섞으면** AI가 "지금 어떤 단계 이야기인지" 혼란
- 단계별 분리 시 시스템 프롬프트(3레이어)와 대화 이력이 일치

#### 진행 상황 추적
- 이전 질문 이력으로 사용자가 **어디서 막혔는지** 파악 가능
- 향후 "이 단계에서 자주 하는 질문" 분석, 개인화된 후속 안내 활용 가능

### 2.2 현실적 한계

| 한계 | 설명 |
|------|------|
| 일반 모드 이력 소실 | 페이지 새로고침하면 대화 사라짐 |
| 노이즈 혼입 | 코치 모드에서 일반 질문해도 해당 단계 스레드에 저장됨 |
| 로드맵 없는 사용자 배제 | 어떤 대화도 보존되지 않음 |

### 2.3 핵심 질문: 꼭 "로드맵별"이어야 하는가?

이력 저장의 이점은 **로드맵 유무와 무관하게** 모든 사용자에게 해당됨.

| 이점 | 로드맵별 필수? |
|------|--------------|
| 대화 연속성 (이어서 질문) | **아니오** — 모든 대화에 필요 |
| 단계별 맥락 분리 | **예** — 시스템 프롬프트와 매칭 |
| 진행 추적/분석 | **예** — 단계 단위가 의미 있음 |

→ **결론**: "대화 이력 저장"을 로드맵 단계에만 묶을 것인가, 아니면 **모든 대화를 저장하되 로드맵 단계 태그만 붙이는 구조**로 갈 것인가?

## 3. 현재 UX의 문제 시나리오

### 시나리오 1: 로드맵 있는 사용자의 일상

```
1. 대시보드 진입 → FAB 클릭 → "AI 어시스턴트" (이력 없음, 빈 화면)
2. "법인 설립 비용이 얼마야?" 질문 → 답변 받음
3. 로드맵 페이지로 이동 → "AI 코치" 버튼 클릭
4. 패널 헤더가 "AI 코치 · 사업자등록"으로 바뀜
5. 이전 대화(법인 설립 비용) 사라짐 → 코치 모드 이력으로 교체
6. 다시 대시보드 가면? → 일반 모드로 돌아가고 모든 대화 사라짐
```

**혼란 포인트**: 같은 패널인데 대화가 왔다 갔다, 일반 모드 대화 영구 소실, "아까 물어본 거 어디 갔지?"

### 시나리오 2: 로드맵 단계 변경

```
1. 1단계(사업자등록) AI 코치로 5번 대화
2. 1단계 완료 → 2단계(영업신고)로 진행
3. 패널 열면 → 2단계 스레드(빈 대화)로 전환
4. "아까 1단계에서 물어본 세무서 관련 내용 다시 보고 싶어"
   → 방법이 없음 (타임라인에서 1단계 클릭해야 함)
```

### 시나리오 3: 코치 모드 중 일반 질문

```
1. 2단계 AI 코치 대화 중
2. "참고로 법인이랑 개인사업자 차이가 뭐야?" (일반적 질문)
3. 현재: 코치 모드로 처리 → 2단계 시스템 프롬프트 적용
   → 답변이 2단계(영업신고) 맥락에 끌려감
```

## 4. 대화 이력 구조별 UX 옵션

### 옵션 A: 단일 대화 스트림 (ChatGPT 스타일)

```
┌─────────────────────┐
│ AI 어시스턴트        │
│─────────────────────│
│ [3/1] 법인 설립 비용?│  ← 일반 질문
│ [3/1] 답변...        │
│ ─── 사업자등록 ───── │  ← 컨텍스트 변경 표시
│ [3/1] 세무서 어디야?  │  ← 코치 질문
│ [3/1] 답변 + [법령 1]│
│ [3/2] 위생교육은?    │  ← 다른 단계
│ [3/2] 답변 + [서류 2]│
└─────────────────────┘
```

- 모든 대화가 시간순으로 한 스트림
- 로드맵 컨텍스트는 내부적으로만 전환
- 사용자는 "모드"를 의식하지 않음

| 장점 | 단점 |
|------|------|
| 직관적, 대화 맥락 안 끊김 | 단계별 시스템 프롬프트 맥락 오염 가능 |
| 가장 단순한 UX | 이력이 길어지면 관련 없는 대화가 노이즈 |

### 옵션 B: 대화방 목록 (Slack/카카오톡 스타일)

```
┌─────────────────────┐
│ [일반] AI 어시스턴트  │  ← 탭 또는 목록
│ [1단계] 사업자등록    │
│ [2단계] 영업신고      │
│─────────────────────│
│ (선택된 대화방 내용)  │
└─────────────────────┘
```

- 각 단계 + 일반이 별도 대화방
- 사용자가 직접 전환

| 장점 | 단점 |
|------|------|
| 단계별 맥락 완벽 분리 | 전환 비용, 복잡도 증가 |
| 깔끔한 이력 관리 | "이게 어떤 대화방이지?" 고민 |

### 옵션 C: 하이브리드 — 자동 컨텍스트 + 통합 이력

```
┌─────────────────────┐
│ AI 어시스턴트        │
│ 📍 2단계·영업신고    │  ← 현재 컨텍스트 표시 (있을 때만)
│─────────────────────│
│ (이 단계 관련 최근   │
│  대화가 자동 로드)   │
│                     │
│ "이전 대화 보기 ▼"  │  ← 다른 단계/일반 대화 접근
└─────────────────────┘
```

- 기본은 단일 대화처럼 보이되
- 로드맵 컨텍스트가 있으면 해당 단계 이력 우선 표시
- 이전 대화(다른 단계/일반)는 접어두거나 별도 접근

| 장점 | 단점 |
|------|------|
| 단순함 유지 + 맥락 분리 | "이전 대화 보기" 설계 추가 필요 |
| 이력 접근 가능 | 자동 전환 시 혼란 가능 |

## 5. 미결정 사항 (다음 논의 필요)

### Q1. 사용자가 "대화방"을 직접 관리해야 하나, 시스템이 자동으로 해야 하나?
- 직접 관리 = 더 통제감, 더 복잡
- 자동 = 더 간편, 하지만 "왜 대화가 바뀌었지?" 혼란 가능

### Q2. 일반 질문의 대화 이력을 저장해야 하나?
- 저장 안 함 = 현재와 동일, 구현 단순
- 저장함 = 모든 대화 보존, 하지만 DB 설계 확장 필요

### Q3. 로드맵 단계를 전환하면 기존 대화는 어떻게 보여야 하나?
- 즉시 교체 vs 구분선 삽입 vs 대화방 분리

### Q4. 챗봇 정체성 통합
- "AI 어시스턴트" vs "AI 코치" 이름을 하나로 통일할 것인가?
- 통일한다면 어떤 이름? (예: "AI 어시스턴트", "StepZero AI" 등)

### Q5. 로드맵 없는 사용자 → 로드맵 생성 후 전환
- 처음엔 일반 모드로 대화
- 로드맵 생성 후 코치 컨텍스트 자동 활성화
- 기존 일반 대화는 어떻게 되나?
