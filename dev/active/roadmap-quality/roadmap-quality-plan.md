# Roadmap Quality Improvement & Business Type Expansion Plan

> Last Updated: 2026-02-25

## Executive Summary

현재 로드맵 생성 시스템은 **휴게음식점** 업종에서만 어느 정도 품질이 나오고, 그 외 업종에서는
"근거 보강 필요" fallback이 빈번하게 발생한다. 벡터DB에 **식품위생법 중심 47개 문서**만
적재되어 있어, 온라인 쇼핑몰/소매업/미용실 등 비음식 업종은 아예 지원이 불가능한 상태이다.

이 계획은 **3단계**로 나누어:
1. 기존 음식점 업종의 품질 안정화
2. 비음식 업종 지원을 위한 법률 문서 확장
3. 업종별 지원 범위 명시 및 UX 개선

을 진행한다.

## Current State Analysis

### DB 분석 결과 (2026-02-25)

| 항목 | 수치 |
|---|---|
| 총 로드맵 | 5개 (휴게음식점 4, 일반음식점 1) |
| 벡터DB 고유 문서 | 47개 (laws 22 + kits 25) |
| "근거 보강 필요" 발생 | **16건** (전체 LEGAL_BASIS 75건 중 21%) |
| 휴게음식점 fallback | 14건 (68건 중 20%) |
| 일반음식점 fallback | 2건 (7건 중 29%) |
| LEGAL_BASIS source_url 보유율 | 휴게음식점 79%, 일반음식점 71% |
| DOCUMENT source_url 보유율 | 휴게음식점 92% |
| generation_mode | 전체 RAG (37건) |

### 핵심 문제점

1. **"근거 보강 필요" 발생 패턴**
   - 마케팅, 인테리어, 메뉴개발, 오픈준비 등 **비법률 단계**에서 집중 발생
   - RAG retriever가 법률 문서만 가져오므로 마케팅/인테리어 관련 법적 근거가 없음
   - fallback 로직: `RoadmapGenerationService._fallback_detail()` → 고정 "근거 보강 필요" 텍스트

2. **업종 범위 제한**
   - 벡터DB: 식품위생법, 건축법, 소방법, 행정법 중심
   - 지원 불가 업종: 통신판매업, 소매업, 미용업, 학원업, 의료업 등
   - validate에서 RAG 기반 정규화 시도 → 법률 문서 없으면 `valid=false`

3. **LLM Personalizer 한계**
   - ActionKit 매칭 결과가 빈약하면 LLM도 품질 높은 출력 불가
   - fallback 시 generic한 "필수 요건 확인" / "근거 보강 필요" 생성

### 현재 벡터DB 문서 커버리지

```

laws/chapter-2: 영업 인허가 - 식품위생법 (3건)  ← 핵심
laws/chapter-3: 소방/다중이용업소 (3건)
laws/chapter-4: 영업 준수사항 (3건)
laws/chapter-5: 행정조사 (1건)
laws/chapter-6: 행정구제 (8건)
kits/legal: 법률 서식 (11건)
kits/tax: 세무 (3건)
kits/hr: 인사노무 (8건)
kits/grant: 정책자금 (3건)
기타: 집단급식소 (1건)
```

## Proposed Future State

### Phase 1: 기존 업종 품질 안정화 (음식점 계열)

비법률 단계(마케팅/인테리어/오픈준비)에서 "근거 보강 필요"가 나오지 않도록
단계 성격에 따라 법적 근거 요구 여부를 구분한다.

**목표**: 휴게음식점/일반음식점의 fallback 비율 21% → 5% 이하

### Phase 2: 비음식 업종 법률 문서 확장

통신판매업, 미용업, 소매업 등 주요 업종별 핵심 법률 문서를 적재한다.

**목표**: 지원 업종 2개 → 8개 이상

### Phase 3: 업종 지원 범위 UX 명시 + 품질 모니터링

프론트엔드에서 지원 업종을 명확히 안내하고, 생성 품질을 지속 모니터링한다.

## Implementation Plan

### Phase 1: 기존 업종 품질 안정화

#### P1-1. 비법률 단계 fallback 로직 개선 (M)
- `_fallback_detail()` / `_generate_phase_detail_with_retry()`에서
  마케팅/인테리어/메뉴개발 등 비법률 단계는 `LEGAL_BASIS`에 "근거 보강 필요" 대신
  해당 단계에 적합한 체크리스트만 생성
- 단계 성격 분류 매핑 추가 (법률필수 / 비법률)
- **AC**: 비법률 단계에서 "근거 보강 필요" 0건

#### P1-2. ActionKit Matcher 검색 쿼리 개선 (S)
- 현재: `"{business_type} {location} 창업 인허가"` 고정 쿼리
- 개선: 단계(phase)별 키워드를 포함한 쿼리 생성
  - 예: 인허가 → "휴게음식점 서울 영업신고 식품위생법"
  - 예: 소방 → "다중이용업소 소방 안전시설"
- **AC**: phase별 키워드 매핑 + retrieval precision 향상

#### P1-3. generation_mode별 품질 태깅 (S)
- 로드맵 생성 시 각 step_detail에 품질 메타데이터 저장
  - `source_count`: 사용된 ActionKit 항목 수
  - `has_fallback`: fallback 사용 여부
- **AC**: roadmap_step_details에 품질 메타 컬럼 추가

#### P1-4. 기존 로드맵 품질 평가 스크립트 (S)
- DB의 모든 로드맵을 분석해서 단계별 품질 리포트 생성
- fallback 비율, source_url 커버리지, 단계별 액션 수 등
- **AC**: `scripts/eval_roadmap_quality.py` 실행 → JSON 리포트

### Phase 2: 비음식 업종 법률 문서 확장

#### P2-1. 우선 확장 업종 선정 및 법률 매핑 (M)

| 우선순위 | 업종 | 핵심 법률 | 비고 |
|---|---|---|---|
| 1 | 통신판매업 (온라인쇼핑몰) | 전자상거래법, 통신판매업 신고 | 수요 높음 |
| 2 | 미용업 | 공중위생관리법 | 1인 창업 다수 |
| 3 | 일반소매업 | 유통산업발전법 | 편의점/소매점 |
| 4 | 학원업 | 학원법 | 교육 창업 |
| 5 | 숙박업 | 공중위생관리법, 관광진흥법 | |
| 6 | 제조업 (식품) | 식품제조가공업 허가 | 식품위생법 확장 |

- **AC**: 업종별 필요 법률 문서 목록 확정 (최소 3개/업종)

#### P2-2. 법률 문서 수집 및 ActionKit 적재 (XL)
- 국가법령정보센터에서 법률/시행령/시행규칙 PDF 수집
- ActionKit 도메인 확장: `laws/chapter-7`~ (업종별)
- 벡터DB 청킹 + 임베딩 적재 (`file_pipeline` 활용)
- **AC**: 업종당 최소 3개 법률 문서 + 벡터 적재 완료
- **의존**: P2-1

#### P2-3. 업종별 카테고리→페이즈 매핑 확장 (M)
- `actionkit_matcher.py`의 `CATEGORY_TO_PHASE` 확장
- 업종별 기본 페이즈 템플릿 정의
  - 음식점: 입지→인허가→소방→세무→인사→오픈
  - 통신판매: 사업자등록→통신판매신고→쇼핑몰구축→결제시스템→세무
  - 미용업: 입지→위생교육→영업신고→시설기준→세무→인사
- **AC**: 6개 업종 페이즈 템플릿 정의 완료
- **의존**: P2-1

#### P2-4. Validate 프롬프트 업종 목록 업데이트 (S)
- `validate_generation_input()`의 프롬프트에 지원 업종 목록 추가
- fallback validation에 새 업종 정규화 규칙 추가
- **AC**: 새 업종 입력 시 `valid=true` + 정규화 성공
- **의존**: P2-2

#### P2-5. ActionKit Matcher 업종별 쿼리 전략 (M)
- 업종에 따라 다른 검색 키워드 전략 적용
- 예: 통신판매업 → "전자상거래 통신판매 신고"
- 예: 미용업 → "공중위생 미용업 신고"
- **AC**: 새 업종에서 ActionKit 매칭 3건 이상
- **의존**: P2-2, P2-3

### Phase 3: UX 개선 + 모니터링

#### P3-1. 프론트엔드 업종 선택 가이드 (M)

#### P3-4. 골든 데이터셋 확장 (M)
