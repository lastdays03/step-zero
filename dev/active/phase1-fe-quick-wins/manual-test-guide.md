## 0. 사전 준비

### 0-1. 서비스 기동

```bash
# 전체 Docker Compose 기동
docker compose -f docker-compose.dev.yml up -d --build

# 서비스 상태 확인 (5개 서비스 모두 healthy/running)
docker compose -f docker-compose.dev.yml ps
```

| 서비스 | URL | 확인 |
|--------|-----|------|
| app-frontend | http://localhost:3000 | 브라우저 접속 |
| app-backend | http://localhost:8000/docs | Swagger UI |
| app-db | localhost:5432 | pg_isready |
| app-redis | localhost:6379 | redis-cli ping |
| app-worker | (no port) | docker logs stepzero-worker |

### 0-2. 테스트 계정 준비

```
# 기존 테스트 계정 사용 또는 회원가입
URL: http://localhost:3000/login
```

### 0-3. localStorage 초기화 (깨끗한 테스트)

브라우저 DevTools > Application > Local Storage > localhost:3000 에서 아래 키 삭제:
- `stepzero_endowed_intro_shown`
- `stepzero_readiness_level_*`
- `stepzero_active_roadmap_id`
- `roadmap_polling_job_id`

### 0-4. 브라우저 준비

- Chrome DevTools 열기 (F12)
- Console 탭 열어두기 (에러 모니터링)
- Network 탭 열어두기 (API 호출 확인)

## 테스트 1: 첫 5분 경험 — 인테이크 정규화 확인 메시지

### 진입 경로
1. 로그인 → http://localhost:3000/roadmap
2. 로드맵이 없으면 자동으로 인테이크 폼 표시
3. 로드맵이 있으면 헤더 오른쪽 "로드맵 전환" → "새 로드맵 만들기" 클릭

### 테스트 시나리오

| # | 동작 | 기대 결과 | Pass/Fail |
|---|------|----------|:---------:|
| 1-1 | "어떤 업종으로 창업을 준비하시나요?" 질문에 `카페` 입력 후 "다음 질문" 클릭 | 채팅 이력에 봇 질문 + 사용자 답변 `카페` + **emerald 배경으로 "✅ 업종을 '카페'(으)로 설정합니다."** 확인 메시지 표시 | |
| 1-2 | "어느 지역에서 시작하시나요?" 질문에 `서울 강남구` 입력 후 "다음 질문" 클릭 | **"✅ 지역을 '서울 강남구'(으)로 설정합니다."** 확인 메시지 표시 | |
| 1-3 | 형태/방식/오픈/예산 각각 답변 후 "다음 질문" 클릭 | 각 답변마다 해당 필드의 **"✅ ... 설정합니다."** 확인 메시지 표시 (총 6개) | |
| 1-4 | 마지막 "추가 설명" (선택 필드) 답변 | **확인 메시지 미표시** (선택 필드는 제외) | |
| 1-5 | 우측 "수집된 정보" 패널 확인 | 6개 필드 모두 입력값 표시 | |
| 1-6 | 칩 클릭 테스트 — 업종 질문에서 "카페" 칩 클릭 | 입력 필드에 "카페" 자동 채워짐 | |

### 확인 포인트
- 확인 메시지는 `emerald-50` 배경 + `✅` 아이콘
- 각 확인 메시지가 해당 답변 바로 아래에 표시
- description(추가 설명) 필드에는 확인 메시지 없음

## 테스트 2: 첫 5분 경험 — 생성 중 동적 메시지

### 진입 경로
1. 테스트 1에서 이어서 — 모든 필수 정보 입력 완료
2. "정보 검증" 클릭 → 검증 완료 후 "로드맵 생성" 클릭

### 테스트 시나리오

| # | 동작 | 기대 결과 | Pass/Fail |
|---|------|----------|:---------:|
| 2-1 | "로드맵 생성" 클릭 후 생성 화면 진입 | 생성 화면 표시 — 스피너 + "로드맵 생성 중입니다" | |
| 2-2 | 상태 표시 확인 | `상태: RUNNING / 단계: {stage} / 진행률: {n}%` 표시 | |
| 2-3 | "현재 작업" 영역 확인 | **동적 stage 메시지 1줄만** 표시 (정적 3개 목록 아님). 예: "업종별 규제를 분석하여 전체 단계를 구성 중입니다..." | |
| 2-4 | stage 변화 관찰 (QUEUED → OUTLINE → DETAIL → SAVING) | stage 변경 시 "현재 작업" 메시지도 동적으로 변경 | |
| 2-5 | 하단 amber 카드 (인사이트 로테이션) | 💡 인사이트 카드가 **5초 간격**으로 fade-out → 다음 메시지 fade-in | |
| 2-6 | 인사이트 내용 확인 | "카페 창업 시...", "개인사업자 등록은...", "위생교육은...", "인테리어 공사 전..." 4개 중 순환 | |
| 2-7 | "생성 화면 닫기" 클릭 | 생성 화면 닫힘, 인테이크 폼으로 복귀 | |

### 확인 포인트
- 정적 3개 항목 ("상위 로드맵 단계 생성" / "단계별 상세 계획" / "결과 저장") **없어야 함**
- 인사이트 카드 fade 트랜지션이 부드러운지 확인 (`transition-opacity duration-500`)
- 생성 완료 시 자동으로 로드맵 실행 뷰로 전환

| 3-5 | **첫 방문 배지 확인** (localStorage 초기화 후) | 파란 배경 배지: **"이미 3단계 준비가 완료되었습니다! 비즈니스 정보 수집, 업종별 규제 분석, 맞춤 로드맵 설계이 끝났습니다."** | |
| 3-6 | 첫 방문 배지 자동 닫힘 | **8초 후** 배지가 사라짐 | |
| 3-7 | 페이지 새로고침 후 재확인 | 첫 방문 배지 **미표시** (1회만 표시) | |

### 테스트 시나리오 — 대시보드

| # | 동작 | 기대 결과 | Pass/Fail |
|---|------|----------|:---------:|
| 3-8 | http://localhost:3000/dashboard 이동 | 대시보드 로드 | |
| 3-9 | ProgressCard 원형 프로그레스 확인 | 퍼센트가 **약 17%** 이상 (0%가 아님) | |
| 3-10 | 원형 프로그레스 내부 라벨 | 퍼센트 숫자 아래 **"준비 단계 포함"** 텍스트 | |

### Endowed 계산 검증

DevTools Console에서 확인:
```javascript
// 로드맵 스텝이 15개이고 0개 완료인 경우:
// (0 + 3) / (15 + 3) = 3/18 ≈ 17%
// 3개 완료인 경우: (3 + 3) / (15 + 3) = 6/18 ≈ 33%
```

## 테스트 4: 다음 3-5 액션 집중 표시

### 진입 경로
1. http://localhost:3000/roadmap (로드맵이 있는 상태)

### 테스트 시나리오

| # | 동작 | 기대 결과 | Pass/Fail |
|---|------|----------|:---------:|
| 4-1 | CURRENT Phase 카드 확인 | 카드 상단에 "Current Phase" 배지 | |
| 4-2 | 표시되는 스텝 수 확인 | **활성 스텝 + 다음 2개 = 최대 3개**만 상세 표시 | |
| 4-3 | 완료된(DONE) 스텝 표시 확인 | 완료된 스텝은 **한 줄 요약** (✅ 아이콘 + 제목, 슬레이트 배경) | |
| 4-4 | "나머지 N개 단계 보기" 버튼 확인 (스텝 4개 이상일 때) | 접힌 스텝 수가 표시된 버튼 존재 | |
| 4-5 | "나머지 N개 단계 보기" 클릭 | 모든 스텝이 펼쳐짐 + 버튼이 **"접기"**로 변경 | |
| 4-6 | "접기" 클릭 | 다시 3개만 표시 | |
| 4-7 | 스텝이 3개 이하인 Phase | "나머지 N개 단계 보기" 버튼 **미표시** | |

### 스텝 상태별 확인

| 상태 | 표시 방식 | 확인 |
|------|----------|:----:|
| DONE (완료) | 한 줄 요약: 체크 아이콘 + 제목 (슬레이트 배경) | |
| ACTIVE (진행 중/다음) | 상세 카드: 체크리스트/서류/법적근거 전체 표시 | |
| LOCKED (잠금) | 점선 테두리 + "이전 단계 완료 후 진행 가능" | |

## 테스트 6: 마일스톤 축하 모먼트

### 6-A. Phase 완료 축하 (컨페티)

| # | 동작 | 기대 결과 | Pass/Fail |
|---|------|----------|:---------:|
| 6-1 | CURRENT Phase의 마지막 스텝에서 "완료 처리" 클릭 | "정말 완료 처리하시겠습니까?" 확인 메시지 | |
| 6-2 | "완료 확인" 클릭 | Phase가 COMPLETED 상태로 전환 | |
| 6-3 | Phase 전환 직후 | **컨페티 애니메이션** (화면 중앙에서 파티클 분사) | |
| 6-4 | 축하 모달 확인 | 반투명 오버레이 + 흰색 모달 카드 | |
| 6-5 | 모달 내용 — 제목 | **"'{Phase명}' 단계 완료!"** | |
| 6-6 | 모달 내용 — 등급 변화 (등급이 변한 경우) | **"{이전 등급} → {현재 등급}"** (파란색 텍스트) | |
| 6-7 | 모달 내용 — 인사이트 | 랜덤 인사이트 메시지 1개 (예: "이 단계를 완료한 창업자의 87%가...") | |
| 6-8 | "계속하기" 버튼 클릭 | 모달 닫힘, 다음 Phase가 CURRENT로 활성화 | |
| 6-9 | 같은 Phase 다시 확인 | COMPLETED 배지 + 접힌 상태, **중복 축하 없음** | |
| 6-10 | 모달 외부 (오버레이) 클릭 | 모달 닫힘 | |

### 6-B. 스텝 완료 랜덤 인사이트 (20%)

| # | 동작 | 기대 결과 | Pass/Fail |
|---|------|----------|:---------:|
| 6-11 | 아무 스텝의 "완료 처리" → "완료 확인" | 스텝 완료 처리 | |
| 6-12 | 약 20% 확률로 인사이트 토스트 표시 | 화면 **하단 중앙**에 슬라이드업 토스트 (흰 카드 + Sparkles 아이콘 + 인사이트 1줄) | |
| 6-13 | 토스트 자동 닫힘 | **3초 후** 자동 사라짐 (fade-out) | |
| 6-14 | 토스트 X 버튼 클릭 | 즉시 닫힘 | |
| 6-15 | 연속 스텝 완료 (30초 이내) | 인사이트 토스트 **미표시** (30초 cooldown) | |
| 6-16 | 30초 후 스텝 완료 | 다시 20% 확률 적용 | |

**팁**: 20% 확률을 강제로 테스트하려면 DevTools Console에서:
```javascript
// Math.random을 일시적으로 오버라이드
const _random = Math.random;
Math.random = () => 0.1; // 항상 20% 미만 → 인사이트 트리거
// 테스트 후 복원: Math.random = _random;
```
